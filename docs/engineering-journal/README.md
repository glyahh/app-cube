# Engineering journal

这是项目的外部记忆，不是流水账。每次解决一个问题，只保留能够帮助未来恢复上下文的最小证据。

## One-case rule

每个案例必须回答五个问题：

1. **现象**：用户或系统看到了什么？
2. **根因**：哪一个边界、状态或依赖导致了现象？
3. **选择**：为什么选择当前方案，而不是更优雅或更简单的方案？
4. **验证**：通过什么源码路径、测试、日志或提交确认？
5. **遗留风险**：什么还没有被证明？

不要逐行记录 AI 生成过程，只记录会影响架构、稳定性、成本和安全的决策。

## Review by risk

拿到 AI 生成的代码后，按以下顺序审查：

1. 数据丢失、重复扣费、权限绕过和错误发布；
2. 并发、线程池、锁、缓存和 TTL；
3. 外部模型调用、超时、重试、取消和 SSE 断开；
4. 数据一致性和失败降级；
5. 最后才是命名、格式和局部优雅性。

## Recovery protocol

忘记一个模块时，不重新通读整个仓库：

```text
打开案例 -> 定位源码路径 -> 查看对应短 SHA -> 重放验证命令
-> 记录当前差异 -> 再开始修改
```
