# 四项功能共同契约：项目、任务、版本与上下文资格

日期：2026-10-03。适用原第一、第二、第三、第五项；原第四项商业视觉暂缓。
状态：目标契约建议，未实现接口、修改协议或迁移数据库。已确认产品行为不因本文件新增工程字段而改变。

关联：[导入](./project-import-design.md)、[测试验收](./project-acceptance-design.md)、[开发衔接](./project-development-workflow-design.md)、[回档](./conversation-rollback-design.md)、[图谱](./code-knowledge-graph-design.md)、[跨功能验收](./cross-feature-consistency-test-matrix.md)。

## 1. 约束顺序与共同原则

产品行为以已确认需求为准；本契约统一同一行为的版本/资格语义；专项文档负责自己的阶段和判定。冲突时先指出，不以技术便利更改产品范围，也不把历史目标文档当当前实现。

身份、内容版本、上下文边界、权限和执行状态是不同维度；appId 相同或源码 hash 相同不能代替全部资格检查。

- 导入永远新建独立 app，不覆盖已有应用，保留新项目生成。
- 同一聊天内部按任务分类；测试可和开发并行，但不能同时不受协调地写同一工作区。
- 模型自然语言、stream succeeded、编译、端口、HTTP 200 均不单独证明业务达标。
- 停止、授权、快照完整性和证据资格不靠 Prompt 保证。
- 不默认降级、缩减步骤或自动生产发布；无法执行如实标失败/未验证。

## 2. 通用身份元组（建议字段）

| 字段 | 含义 | 不可代替 |
| --- | --- | --- |
| ownerId / appId | 用户归属与应用身份，由服务端校验 | 名称、仓库 URL、客户端自报 owner |
| conversationId / branchId | 用户会话与合法对话分支 | Git 分支、原固定 app thread |
| messageId / conversationOrdinal | 用户节点与对话边界，按服务端序列 | 时间戳大小、浏览器消息数组下标 |
| taskId / runId / parentTaskId | 业务任务、一次执行、关联任务 | 单个聊天气泡、Worker PID |
| contextEpoch | 当前允许读取/写入/发布的会话代次 | 源码 hash、工具重启、模型 token 数 |
| workspaceRevision / generation | 工作区受管写入序列与已发布内容代 | Git HEAD、mtime 指纹 |
| snapshotId / contentHash | 某范围内完整输入和内容身份 | 当前可变工作区、仅目录路径 |
| planRevision / approvalRevision | 冻结方案与具体授权版本 | 一个永久“同意”状态 |
| manifestHash / toolVersion | 来源范围、环境/运行器/算法版本 | 单个文件或模型自报版本 |
| operationId / leaseToken | 幂等恢复操作、实际读写/发布资格 | HTTP 已接收、只有 app 锁 |

跨 Java、Python、浏览器的 ID 与雪花序列使用 string，时间可用单独时间字段；客户端不能选择有效 epoch、宿主路径或权限。服务端不能只从 URL 的 appId 推定整个关联链合法。

## 3. 五类版本对象不混用

1. **导入来源**：上传清单或仓库/所选单分支/实际 commit。仅证明来源，不代表后续修改或测试版本。
2. **工作区/回档快照**：受管项目代码、必要配置、属性及排除清单；目标执行前锚点对应明确内容。
3. **测试输入**：独立 source + harness + 固定标准/模板 + 环境/夹具 manifest；测试产生临时输出不能改 source。
4. **图谱索引版本**：允许源码范围、解析器/规则版本、静态依据、Agent 候选与覆盖诊断；模型采样不等于完整可运行/恢复快照。
5. **AI 上下文 seed**：合法消息前缀、摘要来源、工具证据、项目记忆与允许检索范围；不是代码目录或 LangGraph checkpoint id 本身。

可复用内容 blob 与清单机制，但每个用途自己的范围、权限和完整性条件要独立校验。运行 mtime 指纹只做轻量提示；不纳入“内容已相同所以验证可复用”的证明。

必要 `.glyahh/run.json` 等声明要按用途纳入；`.glyahh/reports`、备份、历史日志与模型溢出目录不可因在工程目录就成为当前 AI 源码。用户明确包含敏感配置只授权相应文件接入/受管保存，不自动授予模型读取明文的权限。

## 4. 读写、停止与发布资格

导入凭据的版本/租约与任务最终提交条件补充见[凭据任务契约](./project-import-credential-task-contract.md)。它不是主 Agent 的密钥权限；取消意图、秘密使用资格撤销和实际进程停止分别核验。未提交/恢复中的内容也须阻断静态、预览等读取，不仅隐藏 App 列表。2026-10-03 用户确认在途替换终止旧值未完成任务，提供新凭据重新导入入口，不自动续跑、不在原任务换身份；底层协调机制仍待实现验证。

建议统一工作区闸门/lease：开发写、手动保存、Shell/生成器、运行进程写、快照采集、恢复提交均登记。长时间隔离测试/图谱不占开发锁；建立一致快照短暂协调全部实际写入。

普通源文件变化只增加 workspaceRevision，不等于上下文回档；图谱/测试当前轮按原快照结算，显示是否过期。回档、应用删除、权限撤销是资格撤销事件，应使旧 token 不能写、启动工具或发布当前结果。

任务资源表同时记录宿主进程、容器、服务、端口、数据卷和后台任务；发了 kill/cancel 不代表停止确认。STOP_FAILED 保持逻辑闸门，不能把环境释放给新任务或继续目录恢复。

发布/入库原子核对：完整身份元组、授权 revision、原 snapshot、contextEpoch、事件 seq、operation 幂等与合法终态。迟到结果可按规定保留人类历史证据，但不能改新分支状态、触发修复或写当前项目。

## 5. 同一聊天与内部线程

主开发、隔离测试、图谱补全使用同一 Agent 能力装配，但持久化 execution thread 不能随意共用。建议内部键：

```text
开发：app:{appId}:conversation:{conversationId}:branch:{branchId}:epoch:{contextEpoch}
测试：app:{appId}:test:{testRunId}:epoch:{contextEpoch}
图谱：app:{appId}:knowledge:{indexTaskId}:epoch:{contextEpoch}
```

用户仍看到同一聊天与原工作台；内部 thread 拆分不是两套产品模式。所有历史消息加载/冷启动 historyTail/摘要/SDK store namespace 都须使用同一合法边界，不让旧 `app:{appId}` 默认 resume 绕过裁剪。

`app.initPrompt`、自动标题、项目简介、用户上传说明也可能含撤销内容；若来源包含被回档节点，不作为稳定全局 Prompt 再灌入。原 Prompt 回填输入框不等于允许它进入 seed 或自动发给模型。

项目记忆必须有来源范围，不能存在无 epoch 的全局 store 中；只有明确任务无关的用户偏好可白名单保留。取消独立知识问答，不取消主 Agent 合法图谱检索。

## 6. 权限状态与用户选择一致性表

| 行为 | 默认/触发规则 | 不得发生 |
| --- | --- | --- |
| 文件夹/Git 导入 | 两入口；GitHub/Gitee 公私仓库、多 Token、每次单分支且新 app | 覆盖旧 app、Token 外泄、未确认安装/运行 |
| 依赖准备 | 导入不安装；后续用户确认；拒绝留按钮、运行缺依赖再确认 | 自动执行未知脚本或把“曾安装”当当前环境就绪 |
| 启动 | 手动目录优先；固定扫描→算法识别；两层未识别的部分经用户同意才 Agent 补充，保留已识别结果；手动配置、服务清单可多选 | 未授权调用模型、因已有一个结果禁止补充其他未识别部分、把识别同意当安装/运行授权、无声替换用户目录，默认全启动，单项成功代表整体成功 |
| 运行所需构建 | 点击运行包含所选方案中已列明的必要编译/构建，成功后启动；缺依赖仍须安装确认 | 导入/扫描/独立安装隐式构建启动、构建失败仍启动、额外跑平台验收或部署、用构建绕过新增权限/安装确认 |
| 测试选择 | 首次推荐必测/高风险；复测失败+改动影响，用户决定 | 未选必要项不显示、把未执行记 PASS |
| 测试标准/模板 | 本轮标准冻结，模板新版主动升级 | 修改阈值追溯变绿、活动模板自动改本轮 |
| 新风险 | 建议后确认才执行，未测也进报告 | 无声扩大测试、隐藏待验证风险 |
| 修复 | 独立批准，含相关回归，范围内有进展可继续 | 测试偷偷修、无限盲重试、跨范围写入 |
| 正常回档 | 用户选保留修改或严格恢复，代码/上下文一起退 | 仅文件恢复、恢复错误摘要、保留模式吞冲突 |
| 异常强制 | 合法目标存在、异常时确认丢弃修改 | 绕过停止/备份/权限/完整性/必需验证 |
| 报告 | 短期可看、最小台账；主动下载同时保存项目 | 默认永久完整报告、保存失败假称成功、回档后 Agent 搜索旧报告 |
| 图谱默认 | 用户自动同步默认开，app 图谱默认开、创建时可关 | 自动安装/运行项目，取消问答等于禁 Agent 使用图谱 |
| 关用户自动同步 | 当前轮可完成，不启新自动轮 | 擅自取消当前轮或手动更新 |
| 关 app 图谱 | 停该 app 未完成解析/补全，保留合法历史 | 停主开发/其他 app，迟到旧任务发布 |
| 图谱补全失败 | 通知后额外重试一次，仍失败不自动发静态半成品 | 无限重试、静默降级、把推断当事实 |

安装/启动、测试、图谱同步和回档分别有权限/生命周期，不能用一个用户全局“模式”掩盖差异。

运行专项建议见[启动计划契约](./project-import-startup-plan-contract.md)。候选识别、Agent 只读授权、缺依赖安装确认和本次运行批准分开；计划绑定内容与配置版本，旧准备/就绪结果不能证明新工作区可用。当前 stop 返回成功及 mtime 指纹不足以支撑这组目标约束，仍需实现和实际验证。

## 7. 缓存与恢复后的资格

- 普通代码修改：历史结果保留 snapshot，当前 UI 标过期，不能代表最新版本。
- 回档：旧分支所有派生摘要/工具/测试/图谱推断/store 失去当前可读资格，即使内容 hash 相同。
- 独立确定性静态缓存：仅与源码内容、解析器/规则/完整范围匹配且无旧对话/推断依赖时，由新任务重新验证归属后引用；不能顺带恢复旧候选边或已撤销报告解释。
- 回档后默认勾选失败项只能来自当前合法分支/代次中的记录；被撤销错误路径不进入推荐或模型请求。
- 当前保留的 user_manual/user_approved 代码可以重新解析和验证，事实来自最终文件，不来自错误过程的回忆。

范围未知、缓存截断、秘密/权限变化时拒绝复用，不声称确定性或覆盖完整。标识与文件 hash 只证明一致性，不证明工具结果诚实或业务正确。

## 8. 失败、保存与清理

结构化结果至少分执行状态、断言结果、版本资格。图谱成功发布、测试轮次完成、开发任务验证成功、回档提交成功具有不同门禁，不将一个 succeeded 布尔传播给所有功能。

临时证据、完整报告、代码快照与用户主动保存的项目文件分别定义保留策略；本轮不编造统一天数。引用中的快照/backup、未停止资源、保存进行中不得清理；采用绝对路径和归属核验，不能跨应用或跟随链接删除。

回档点保留政策已单独确认 A：全部有效点默认保留至用户主动清理，不按天数或数量自动淘汰；底层压缩/去重不损害可恢复性，容量不足明示处理。完整测试报告与临时日志仍按各自策略管理，不因该选择默认永久保存，也不能反过来用报告到期清理回档依赖。

报告主动保存是用户授权的写动作，不由测试 Agent 写业务目录。保存到受管平台报告区但仍可下载；不让当前检索自动读旧报告，也不将报告保存造成的源码无关变化触发虚假的业务版本更新。

## 9. 目标协议迁移建议（尚未实施）

1. 保留当前 NDJSON v1 与旧生成能力；新增能力协商与完整资格字段，不直接给旧 worker 一个未知 taskKind（当前会落到可写 coding）。
2. Java 构造服务端有效请求，Python 校验类型/资格并使用专属执行策略。测试受限写测试目录，分析只读，开发按批准范围，不使用客户端自报权限。
3. 新契约逐步接入手动保存、Shell、运行/知识/测试与检索；每个入口保留回归。任何未受管写通道都阻止宣称回档全面可用。
4. 迁移已有 app 固定 thread 的历史：只能从可证明合法原文投影；历史无快照/来源不补造。用户看到缺资格原因，不能偷偷丢历史后称迁移完工。
5. 实施双端更新时再改实际 `docs/AGENT_CONTRACT.md` 与 schema/测试；本文件是未来目标，不改写当前实际协议。

## 10. 必须证明的全链路不变量

- 同一 app 的写入、快照和回档具备一致边界；隔离读任务不阻塞开发、不修改当前项目。
- 每条结果属于唯一 app/task/snapshot/标准/epoch，不使用新文件解释旧执行成功。
- 回档新代码与新 seed 一起发布，旧资源和派生上下文不可读写；数据库不自动恢复。
- 全部四项共享身份和取消资格，但分别遵守产品开关与生命周期。
- 文档、实现、实际验证、交付/发布状态分开。对应跨功能矩阵全部待执行。
