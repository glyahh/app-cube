## 5. 执行证据格式

每个实际用例至少记录：用例与子场景、输入/前置状态、预期、实际结果、状态、时间、平台代码 commit、测试工程来源与内容版本、用户/应用/任务/服务标识、执行环境、实际命令和退出码、脱敏日志或断言输出、最终文件/业务状态、证据路径。

- `PASS`：实际执行满足预期，并有当前版本证据。
- `FAIL`：已执行且不满足预期，保留失败证据与问题关联。
- `NOT_RUN`：没有执行，不能计为通过。
- `BLOCKED`：缺少凭据、环境、实现或已确认规则等条件，列明阻断原因。
- `NOT_APPLICABLE`：仅在已确认范围确实不适用时使用，给出依据，不代替缺失能力。

建议实现后使用独立证据目录与结果清单，各次运行不覆盖旧证据；目录位置在实施时确认。秘密值不进入清单、日志、命令文本或截图。
