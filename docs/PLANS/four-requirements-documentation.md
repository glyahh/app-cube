## 2. 需求落点与关键差距

### 第一项：导入已有项目

同时保留文件夹上传、GitHub/Gitee 公私仓库导入；用户可保存多份 Token，通过辅助按钮进入获取页面，单次选择一个分支，创建独立新应用，不覆盖原应用或原工程。首次不安装、不启动；安装询问、保留按钮、运行缺依赖提醒，以及目录/多服务选择均按既有设计。

后续澄清已确认启动识别三层顺序：固定扫描、算法识别、Agent 识别。前两层都未识别的部分须用户同意才使用 Agent，保留已有识别结果，不要求整个项目零结果；识别不隐含安装或运行授权。

运行授权也已确认包含所选方案中已列明的必要编译/构建，成功后启动服务；缺依赖仍询问安装，不额外触发平台验收或部署。导入/扫描/单独安装不隐式构建运行。

现有运行识别、路径保护与应用工作区可复用，但不能当作已经实现导入、Token 保护、完整服务发现与真实运行验收。

### 第二项：测试与交付判断

平台基准、项目个性化测试、用户自然语言定制规则共同服务实际业务。用户决定本次清单；适用必要细项逐项达标，综合评分不能覆盖失败、未测或无法执行项。工具指标、Agent 执行质量与问卷答案各自保留依据，不能互相冒充实际验证。

后台测试使用固定版本的独立副本，允许原项目继续开发。测试不自动修业务代码，报告不默认永久保存；用户主动下载/保存到项目，旧报告不得自动污染新版本判断或回档后上下文。

### 第三项：开发衔接与回档

统一聊天与 Agent 能力，开发/测试是任务内部职责与权限状态。修复先批准方案与范围；旧问题在最新代码复现，最小改动后回归；失败不得隐藏，也不默认发布生产。

每条用户消息绑定真实执行前锚点。常规回档可选保留用户修改或严格恢复；异常时提供强制入口，但不能绕过停止、备份、归属和必要验证。Patch 级来源、用户明确认可、三方合并、语义验证与失败 journal 共同保护代码；代码恢复与模型上下文同时建立新合法边界。保护快照和旧分支仅供人类只读，不让当前 Agent 读取。不改用户 Git 历史；首期不恢复项目数据库。

长期保留已确认 A：有效回档点默认保留至用户主动清理，不自动按时间/数量淘汰，容量不足明示。Claude Code 参考范围也已确认 A：参考整体交互与检查点机制，不照搬其保留/覆盖限制，保留本项目既定增强要求；不宣称底层实现已接入或已验收。

### 第五项：四层知识图谱

保留总体架构、文件依赖/归属与数据流、模块内文件职责、方法关系四层，由表及里。沿用已有工作台，节点灵动、清晰、流畅，不强制星环。独立问答、学习导览与海报不纳入。

首层组织方式已确认 A：默认技术协作架构，展示当前工程真实组件及边界如何连接，节点内保留业务职责；不增加模式页，不将所有工程套成 Web 三层结构。

全语言是覆盖目标，不是现有 Tree-sitter grammar 或静态分析已覆盖一切的结论。通用解析、语言适配与 Agent 补全统一模型；确定关系与推断分开，未知/不支持不能伪造。图谱默认开启，单应用与自动同步开关各自生效；失败显式提示并按专项规则额外重试一次，不自动发布缩水版新图。

## 3. 已确认与待验证必须分开

| 类型 | 处理方式 |
| --- | --- |
| 用户已确认的范围、交互、权限与失败原则 | 作为产品约束，不反复重问显然的选择题 |
| 状态机、数据结构、协议字段、归因和合并适配建议 | 作为研发设计，审阅后再实现，不称现有能力 |
| 全语言解析、数据流可靠性、语义校验、停止收敛 | 用真实样本与环境逐项证明，未知如实记录 |
| 性能、资源、保留期及指标阈值 | 实施前依据样本校准，不编造数字、不用预算掩盖失败 |
| 开源工具与基准 | 官方资料仅证明定位；版本、许可、镜像与输出适配须验证 |
| 静态视觉稿、人工图谱 JSON、待执行矩阵 | 设计工件，不是前端完成、解析结果或测试证据 |
