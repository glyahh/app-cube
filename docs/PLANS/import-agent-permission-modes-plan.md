# 导入 Agent 编辑：会话授权模式与统一门禁计划

状态：BACKEND_IN_PROGRESS。独立前端审核版已实现；后端主体已在工作区实现，但未提交、未验收。日期：2026-10-10（2026-10-17 回填）。

本计划按用户新决定替代 `import-agent-change-review-plan.md` 中“所有结果一律人工确认”的产品策略；仍复用其中候选绑定、独立校验、差异展示、CAS 与恢复要求。旧计划不再作为全模式的开发要求。

本轮按用户要求先制作独立前端审核版，审核通过后再推进后端；不改正式授权入口、不运行迁移、不启动服务。第一项原批准交付范围仍为 COMPLETE；这是新增能力。前端边界与检查记录见 [前端审核记录](import-agent-permission-modes-frontend-review.md)。2026-10-17 回填：后端实现已写入工作区（含 V40），但尚未提交、未运行迁移、未验收；实际进度见文末「实施进度」。

## 1. 产品决定

会话输入区域旁提供三个选择，作用于当前导入应用会话：

| 模式 | 只读操作 | 隔离视图内普通写操作 | 高风险合法操作 | 最终候选合入 |
|---|---|---|---|---|
| 手动批准 MANUAL | 自动执行 | 执行前询问 | 执行前询问 | 整批人工确认 |
| 自动批准 GUARDED_AUTO | 确定性纯读取自动执行 | AI 审查为非高风险后自动批准 | AI 审查为高风险后询问用户 | AI 审查整批候选，非高风险可自动；含高风险必须整批确认 |
| 自由发挥 AUTO | 自动执行 | 自动批准 | 自动批准 | 校验通过且取得合法自动决策后自动合入 |

三种模式都不能突破硬禁止项，也不能把校验失败变成成功。“手动批准”不要求用户确认每次读取，也不表示用户亲自写代码。

上表是尚无匹配会话同类授权时的默认行为。MANUAL/GUARDED_AUTO 已由用户授予的有效同类工具范围按 §3.1 免重复询问，不降低风险等级；最终候选仍遵循表中规则。

自由发挥是用户事先授权的一种策略，不是异常后的降级路径。风险判定只决定是否询问，不判断业务修改是否正确；自动模式无法保证普通业务逻辑不会被改错。

本期只覆盖导入项目的 Agent 代码编辑、检查命令及源码合入。依赖安装、服务启动、部署、远端 Git 推送继续使用各自既有授权；自由发挥不能暗中扩大这些范围。新项目生成与知识只读任务不在本轮改造范围。

## 2. 先硬边界，再风险，再模式

统一决定顺序：

1. 校验当前项目、编辑身份、路径、资格、资源与原有工具规则；命中硬禁止即 DENY。
2. 自动批准模式下，由服务端调用 AI 审查准确的待执行操作及上下文，判断高风险或非高风险并给出原因；不是只按平台路径规则自动批准。
3. 按本轮冻结模式返回 ALLOW 或 ASK，写入可审计决策。
4. 真正执行前核对批准对象仍相同，消费单次授权；禁止模型自行改 mode 或伪造批准。

不能实现成“如果 AUTO 就跳过权限校验”。策略读取失败、摘要无法生成、协议错误均失败并明确通知，不默认按 AUTO 执行。

### 2.1 硬禁止，所有模式一致

保留全部现有拒绝：跨工作区访问、受保护路径、秘密映射或原值读取、未授权源码合入、Shell 偷改授权、危险命令/操作符、伪造身份、失效资格、资源限额无法证明、候选/原版本不一致。

危险命令不允许“用户点批准就解禁”；禁止项与可询问项分别显示。具体保护列表以现有实现为准，不在本次缩减。

### 2.2 AI 风险审查与平台底线

自动批准模式由 AI 审查实际动作、文件差异或命令及其上下文。平台继续执行硬禁止项和既有高风险最低规则；AI 可提高风险，不可降低明确的安全底线。执行 Agent 自报的 low/high 不作为审查结果。以下规则同时作为 AI 审查重点：

- 文件删除、批量覆盖/上传、文件权限模式变化。
- 常规配置与依赖文件：config*.json、application*.yml/properties、package*.json/lock、pom.xml、requirements*.txt、uv.lock 等；其中原本受保护的配置仍直接禁止。
- 脚本、Docker/CI、迁移及运行声明：scripts/、Dockerfile、compose*、.github/、数据库迁移目录、.glyahh/run.json 等。
- README 等说明文件纳入高风险，防止其在默认自动模式下不经询问被改动。
- 涉及鉴权、权限或数据操作的既有固定目录/文件规则；不声称路径规则能够识别全部业务语义。
- 新可执行文件、超过固定文件数/字节预算的修改、无法显示正文的二进制变更。
- 可执行工程代码的命令：python/node 脚本、pytest、npm scripts、构建、Git 写操作等。不能因叫 test/build 就判为只读；其脚本和依赖可能产生副作用。
- 合法但无法证明低风险的操作归 HIGH。无法解析或不满足原工具白名单的命令直接 DENY，不通过归 HIGH 放开。

非高风险放行必须同时满足原工具校验、明确允许范围及服务端 AI 审查结果；例如合法业务源码的非删除小范围修改。确定性纯读取工具和白名单纯查询命令仍按既有只读规则执行。审查结果绑定实际 actionHash、上下文与规则版本；参数或前置内容变化后重新审查。审查调用失败、结果缺失或格式错误时明确报错，不默认放行，也不静默切换为纯规则审批。

命令批准绑定规范化 argv、工作目录、实际执行的脚本/项目声明/锁文件摘要及视图版本；绑定文件变化后必须重新决策。执行未能完整界定的外部副作用，不属于“低风险自动运行”。

## 3. UI 与会话作用域

- 在 AppChatView 输入区旁使用现有 Ant Design Vue 分段选择或紧凑下拉；常驻只显示当前模式，不新增常驻大说明块。
- 三个标签使用用户指定文案；不提供问号帮助入口。
- 推荐新导入会话默认 MANUAL。若以后要默认 GUARDED_AUTO，应单独确认；本期不在账号偏好里静默开启自由发挥。
- 选择 AUTO（自由发挥）后直接保存，不显示二次授权弹窗；用户主动选择模式作为授权动作，仍以服务端保存成功为生效条件。
- 保存成功后才显示新模式；失败保留原模式并显示错误。服务器值是权威，不用 localStorage 或页面变量充当授权。
- 当前任务执行中或有待批准项时，模式选择禁用；用户可取消本轮后改模式重跑。模式变更只作用下一轮，不把已有 ASK 自动变为 ALLOW。
- 会话刷新恢复服务器设置；其他应用/账号不继承。多页面修改用 policyRevision CAS，不能最后写入静默覆盖。
- ASK 标题右侧展示淡化的对象名，窄屏允许换行；删除普通修改的重复说明及单次授权常驻提示，保留高风险原因与最终候选提示。操作提供“拒绝并停止本轮”“仅批准本次”“本会话批准同类请求”。同类批准适用于 MANUAL 与 GUARDED_AUTO，不是永久允许。
- 用户拒绝后停止本轮，进入现有清理，不让模型不断改写参数重复索要批准。
- 保留键盘操作、焦点、文字状态和现有空行/间距层级；颜色不是唯一风险提示。差异纯文本渲染，窄屏不挤出横向滚动。

模式权威范围为 ownerId + appId + 服务端确认的 threadId（当前通常 app:{appId}）。不同浏览器窗口不是不同权限会话，不接受客户端任意 threadId 跨项目设权限。

### 3.1 本会话批准同类请求

用户主动选择后，批准当前操作，并在当前权限会话内记住明确范围；后续匹配请求不再询问，跨本会话的任务轮次和模式切换仍有效。“仅批准本次”不创建会话授权，最终候选不提供同类批准按钮。

- 匹配条件：相同工具动作、风险等级和目标范围。普通文件修改限于当前目录；高风险文件修改限于当前文件；命令限于相同规范化命令、工作目录及脚本/声明/锁文件摘要。删除、上传等动作不能继承修改文件授权。
- 每次仍先校验硬禁止、资格、资源与实际风险；风险提高、目标超出范围或命令绑定变化必须重新询问。AI 审查失败仍报错，不用同类授权掩盖失败。
- 最终整批合入、安装、启动、部署、远端推送不在同类工具授权内，继续遵循各自决策规则。批准失败、冲突或对象失效不创建会话授权。
- 正式权限会话由服务器绑定 owner/app/thread 和 sessionEpoch，不接受客户端自行扩大范围。结束会话、到期、重启或安全规则代次变化使授权失效；不跨账号/项目继承。正式刷新恢复仍从服务器读取，不靠 localStorage。
- 当前独立预览仅保存在组件内存，刷新或重建页面即清空，不代表正式会话生命周期或恢复已实现。

## 4. 数据与职责

最小建设，不引入审批引擎、消息队列或额外模型供应商；风险审查复用现有模型配置，由服务端发起独立审查调用，与执行 Agent 的自评分开。

### 4.1 会话策略

新增会话策略登记：owner/app/thread 唯一，mode、policyRevision、riskPolicyVersion。写入需登录、归属及 CSRF 校验。

开始编辑时将 mode、policyRevision、riskPolicyVersion 冻结进编辑账本；加入不可变身份守卫。Java 下发，Python 校验，不从用户 prompt、模型输出或前端未经保存的选项决定权限。

### 4.2 单次工具授权

新增单次权限请求登记：requestId/callId、editId、workerLeaseId、toolKind、相对路径/命令指纹、beforeHash、argumentsHash、actionHash、风险与原因、AI 审查身份及结果摘要、策略身份、到期时间、决定来源、状态。

- 决定来源区分 USER、AUTO_POLICY；会话同类授权派生票据仍记录 USER，并关联 sessionGrantId，不冒充逐项人工审阅。AUTO_POLICY 不是“用户已看过”。
- actionHash 覆盖准确的操作与执行参数；只批准一次对象，不批准通配路径。
- 参数/前置字节/视图版本变化使票据失效；重建请求，不能沿用旧票据。
- 票据批准与执行许可消费均使用 CAS；同 callId 不重复执行。副作用开始后失败不自动重试。
- 不持久公开秘密正文或映射；审批预览与真实批准指纹分开，脱敏不能改变实际执行对象。

正式接线需登记会话同类授权范围、风险等级、sessionEpoch、规则代次、期限与授予请求。与当前请求批准原子写入，只有绑定对象仍有效且 CAS 成功才生效；每次匹配仍签发绑定实际 actionHash 的新单次票据，不能重用已消费票据。当前仅前端演示，尚未新增此登记。

### 4.3 最终候选决策

保留前计划的 immutable review 清单：候选、manifest、授权摘要、完整 changes、源版本、等待 revision、reviewHash。

所有模式先完成 Java 独立验证；自动批准模式再由服务端针对实际完整 changes 调用 AI 重新审查风险，并保留平台安全底线。工具级 AI 审查不能代替最终候选审查，不能仅采信执行 Agent 的风险标签或摘要。

- MANUAL：必须 USER 批准。
- GUARDED_AUTO：存在 HIGH 则 USER；全部 LOW 才允许 AUTO_POLICY。
- AUTO：合法候选允许 AUTO_POLICY。

自动合入也要登记与实际候选绑定的决策，包含模式与风险规则版本。不能保留“没有任何决策但直接 publish”的捷径。工具批准不能代替最终整批候选批准，两者的对象与发生时间不同。

## 5. Java / Python 接线

### 5.1 工具执行前门禁

统一覆盖 SecretFreeDockerBackend 的 write、edit、delete、upload_files、execute。门禁必须位于 _start_edit/super.* 之前，不能先改文件再弹确认；逐项覆盖单文件和批量入口。

复用 prepare_import_command 做原有语法/白名单/路径校验，之后再做风险与模式判断。不要把该安全校验替换成风险评分。

Python 发 `import.permission.requested` 内部事件；Java 核对身份、重算可核对的请求指纹、登记票据并发前端安全事件。Python 无权写 biz 批准表。

本期推荐通过现有 PostgreSQL 只读资格通道等待 Java 决策，不新增 HTTP 服务或争抢 stdin 的第二个读取者：

1. Python 产生请求并暂停该工具，Java 登记/决定。
2. 用户 REST 决定或 Java AUTO_POLICY 决定更新票据。
3. Python 查询严格绑定 edit/lease/callId 的决定。
4. 执行前发一次许可消费请求，Java CAS 消费并回写可读证明；Python 校验证明及当前实际参数/前置摘要后才执行。
5. 工具完成事件关联票据，不把“批准”当作“执行成功”。

消费票据不保证工程脚本副作用 exactly-once。崩溃发生在许可消费之后，结果明确记为未确认；停止并清理，不重放。更新数据库角色权限时仅允许 native Worker 读取必需列，不增加批准表写权限或泄露其他用户数据。

这是新增内部事件/只读查询能力，必须同时更新 AGENT_CONTRACT、事件序号校验、过滤器与审计；不能通过普通 text.message 解析“用户同意”来批准。

### 5.2 两种等待不同

- 工具等待：本轮模型停在工具边界，保留 Worker 和容器，继续计入资源与并发额度；没有工程命令正在执行。单请求有短时限、心跳和总体时限，取消即撤销票据并停执行者。不得为 ASK 无限延长租约，也不得等待超时自动批准。
- 最终候选等待：Worker/容器已停止，归还槽位并结束执行流；保留候选与卷登记，用数据库占用保护代替长期内存锁。

手动批准会更多占用等待中的 Worker，这是明确成本。实现有界等待和并发准入，不另造无限等待进程池。

SSE 和 WebSocket 共用 REST 决策接口；页面刷新找回当前请求。等待阶段断连不是拒绝，但不能改变本轮固定过期时间。

### 5.3 发布与恢复

发布入口统一核对本轮策略、候选独立验证证据、USER/AUTO_POLICY 决定及对应准确摘要。取消、原版本、配置 epoch、实际候选字节仍在关键提交点复核。

需要最终人工批准时新增 WAITING_REVIEW；父候选哈希可继续留到 beginPublication 再写，审阅绑定单独持久化。移交等待后的 finally 不释放候选；移交失败仍走原清理。

拒绝票据/候选、到期、停止与重启使用既有安全撤销和资源收口。推荐本期重启取消旧等待与旧执行，不恢复旧权限票据；COMMITTING/COMMITTED 保持原发布阶段恢复规则，不能回退已提交源码。

agent_run 需区分工具暂停与最终待确认：前者仍 RUNNING 加明确 phase，后者 WAITING_REVIEW。不能因流结束默认 FAILED 或提前 SUCCEEDED；对账、聊天和成功事件同步调整。

## 6. 现在代码哪些逻辑要删除或替换

这里是未来实施清单，不是本次已删除内容。优先替换条件和提取委托，不大面积删除已有安全实现。

### 6.1 必须删除的无条件行为

1. **ImportAgentEditExecution.execute() 中 verify 后无条件 publish。** 替换为“生成绑定清单、确定模式决策、自动取得候选许可或移交等待”，再调用统一发布服务。
2. **ImportAgentPublication.publish(editId, ownerId) 的无条件 `()->true` 资格捷径。** 方法可保留兼容入口，但必须委托统一决策校验；不能让普通内部调用绕过模式和批准。
3. **ImportAgentEditLedger.beginPublication() 只凭 qualifiedSealing/candidateProof 就进入 COMMITTING。** 替换为数据库验证相同候选的有效 USER/AUTO_POLICY 决策，保留旧独立验证条件。
4. **SecretFreeDockerBackend 中通过 editable 就直接 _start_edit/super.* 的执行路径。** 插入单次许可消费；原校验、写入与 record_edit 仍在同一保护流程内。
5. **SecretFreeDockerBackend.execute() 通过现有命令校验后直接运行的路径。** 在实际 manager.execute 前加入命令许可门禁；不能只在前端禁止执行。
6. **主状态守卫里无决策证据的 SEALING → COMMITTING。** 自动与人工都必须有合法决定；人工候选经 WAITING_REVIEW，自动候选可在冻结 AUTO_POLICY 决策后直接进入 COMMITTING。

### 6.2 必须缩小适用范围的现有行为

7. **execute.finally 中所有未 successful 结果都进入失败/取消清理。** 增加“已持久移交 WAITING_REVIEW”分支，除此之外保持真实停止/恢复保护。
8. **AgentRunPersistence.tap() 中正常流结束默认 FAILED，以及取消信号一律登记 CANCELLED。** 对合法候选等待按数据库状态记 WAITING_REVIEW；真实取消仍取消，不能吞掉取消竞态。
9. **ImportNativeWorker.read() 与执行流总时限把用户等待当作无事件故障。** 加入有界等待心跳/phase，不删读取超时，不取消总体时限。
10. **Python eligible 仅状态 EDITING 的假设。** 本期工具等待不新增父状态，仍 EDITING 加权限票据 phase；若实现改成新父状态，须全链同步，不能简单允许任何等待态执行。
11. **释放 AppRunCoordinator 后只凭 publication READY 允许新编辑的假设。** 等待候选必须通过数据库未关闭编辑记录，在锁内统一阻止同应用写入、安装/运行、配置修改与删除；只读允许。

## 9. 验收门禁

- MANUAL 普通源码工具未批准前无文件变化，批准后只执行一次；最终候选未批准不合入。
- GUARDED_AUTO 合法普通源码经 AI 审查为非高风险才自动放行；AI 判高风险或命中平台高风险底线时询问用户；即使工具已批准，最终高风险候选仍按完整版本确认。
- AUTO 合法高风险自动，无人工弹窗；同样有绑定实际动作与候选的自动决策审计。
- 三模式下秘密路径、危险命令、Shell 偷改、跨应用、旧资格和校验失败全部拒绝。
- 执行 Agent 伪造模式或 risk、伪造服务端 AI 审查结果、修改工具参数/前置文件、票据重复使用、旧 revision/哈希、跨账号批准均拒绝。
- 并发批准/拒绝/取消/到期只产生一个合法结果；许可消费后崩溃不自动重复副作用。
- 任务中模式无法更改；其他会话模式不串；多标签页 CAS 冲突明确。
- MANUAL/GUARDED_AUTO 同类批准在本权限会话内跨轮有效；不同动作/风险/目标范围、命令绑定变化、其他会话及失效代次不能继承。失败决定不得保存授权，每次执行均消费新的实际对象票据；最终合入不被工具会话授权覆盖。
- 工具等待与最终等待分别测试断连、刷新、到期、重启；资源未确认清理时保留占用，不报全成功。
- AI 审查失败、结果缺失或格式错误不能默认自动放行；平台风险底线不能被 AI 下调，无法解析命令仍拒绝；命令 scripts/lock/dependency 摘要变化使审查和批准失效。
- SSE/WS/真实浏览器三模式都走到真实文件读回；未完成环境验收标为未执行。
- 秘密不进审批预览/HTTP/事件/聊天，XSS 纯文本不执行；非导入任务及既有安全回归不受影响。

最终交付记录当前代码版本、命令、退出码、原始失败与清理读回。不把“自动批准”显示为人工检查，不把合入成功显示为业务验收成功。
