## 3. 矩阵之外仍需显式展开的契约断言

以下是原矩阵的子用例，不另凑“通过数量”：

1. C02/E01：逐入口查静态文件、文件树、下载、Agent、运行、图谱；暂存/恢复中内容都不可读。匿名、他人、删除 app、过期任务分别测。会话/CSRF 规则复用现有机制并测试，不能信客户端 ownerId。
2. C04/R06：准备、远端读取、扫描、待确认、待提交、提交两侧分别插入替换/删除/取消；共享提交条件决定唯一结果。停止失败与清理失败分开记录。修改备注不撤销；旧任务不自动续跑或换身份。
3. E01：封存前后、文件移动前后、SQL 提交前后、成功事件前后、清理失败、Windows 文件占用、平台重启逐点注入；恢复不覆盖成功后合法编辑。
4. S07/D07/R06：同大小同 mtime 改内容、run.json 改动、配置/批准版本改变、权限撤销、乱序/重复事件；旧结果不得改当前状态。元数据清单绝不是内容快照。
5. G08/C03：隔离 Git HOME/helper，不读个人 GCM/SSH；跨 provider/用户秘密错配和重定向泄漏。测试只能用专用虚构标记及专用测试凭据。
6. D05/R03：构建阶段才发现下载需求，未批准就停；不得追加 skipTests、隐式部署或平台验收。安装脚本子进程也登记，不能只看表面命令。
7. 共同契约对应跨项矩阵 X15/X17/X18 及受影响条目：本项做身份、撤销、清理边界测试；尚未实现的回档/图谱/验收联动保持 NOT_RUN，不冒充跨项通过。

## 4. 样本、环境与证据

- 基础样本：Node/Vue、Java Spring Boot、Python Web、静态页面及前后端多服务。每个样本固定工具/框架/锁文件/内容 hash、预期服务与业务请求；运行版本支持清单在实跑后建立，不由样本名字推断支持。
- 负例：恶意路径/链接/大小、损坏配置、冲突锁文件、缺入口、读失败、非法秘密标记、失败安装/构建/服务、端口冲突、超时/停不掉/磁盘满、版本变动。只有隔离测试环境执行工程代码。
- 分离来源、受管 staging、可用工作区、执行副本、测试代码、保护快照及证据目录。清理测试前校验绝对路径和归属；不删除用户目录。
- 先复用 JUnit/Mockito/MockMvc、Vitest/Playwright、pytest；不安装新框架。单元和故障 fake 不代替 PostgreSQL、Redis、两个 Git 平台和 Docker 真链路。
- 每次记录：矩阵 ID/子用例、前置状态/输入、预期/实际、PASS/FAIL/NOT_RUN/BLOCKED、时间、平台 HEAD+脏文件 hash、样本内容身份、owner/app/task/service/version/context、工具环境、命令/退出码、脱敏日志、最终 DB/文件/进程、证据路径。没有标识的纯函数测试写“不涉及”，不能编造业务任务。
- Git 公开/私有真实测试仓库与专用 Token、可隔离 DB/Redis、执行镜像和额度未验证前，列具体缺口。不读取个人凭据，不用生产数据补测试。

## 5. 当前小步与后续门禁

1. **清单校验**：先写可运行失败测试，再实现纯 Java 校验器，无 HTTP、DB、文件写入、模型调用或工程执行。数量/字节额度由调用方显式传入，不能把浏览器 10,000 文件上限当最终服务额度。
2. **上传/任务/确认**：再确定真实字节校验、归属、staging、任务与封存内容版本、取消、接口错误。前端 `service.ts` 暂不接一个只返回清单的接口冒充上传。
3. **提交/恢复**：先覆盖各读取入口和 journal 故障点，再允许生成可用 app。事务、目录存在、上传结束不能各自单独判成功。
4. **Git/凭据/偏好**：完成对应前端评审，逐平台和逐契约实现验证。
5. **识别/安装/多服务**：按专项契约逐步增加并独立验收；当前不改旧运行架构。
6. **完整交付**：全部适用矩阵子场景实跑、必要既有回归、干净回放与跨项边界检查完成才交付第一项。没有用新测试能力提前开发第二项。
