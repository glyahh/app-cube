# 会话回档：来源、合并、上下文与失败恢复验收

日期：2026-10-03。对应[回档设计](./conversation-rollback-design.md)。全部待执行；没有本轮运行、合并、模型请求或通过数字。

## 1. 证据要求

每个用例记录 appId、消息/任务、旧/新 branchId/contextEpoch、目标/当前/候选/backup 内容清单与 hash、保留 ChangeSet、批准 revision、恢复方式、真实资源停止状态、journal 决策、最终文件、验证输出和真正发模型的请求。秘密用虚构哨兵，不泄露真实凭据。

至少以原始与干净重建两套副本回放。文件变更、提交前后故障、模型上下文采集应由确定性断言核验，不由 Agent 说“已经忘记”验收。

## 2. 用例清单

| ID | 阶段 | 场景 | 必须结果 |
| --- | --- | --- | --- |
| R01 | 前端 | 任意用户消息显示回档，目标执行前有真实锚点 | 写代码/只读/测试消息均可选择，不仅最后一轮；未准备/缺快照如实不可恢复 |
| R02 | 前端 | 正常选择保留修改或严格恢复 | 两种方式含代码与上下文；损失范围清楚，不将严格方式误当异常强制 |
| R03 | 前端 | 回档成功后提示词回填 | 原文/附件引用合法回填，不自动发送、不继续旧工具；回填失败不显完整成功 |
| R04 | 锚点 | 两条无代码变化的不同用户消息 | 可以复用内容 blob，但上下文边界不同，回档不能删错前缀 |
| R05 | 锚点 | 排队/中途补充消息 | 执行前建立真实边界或独立排队，不在无 checkpoint 情况继续写入 |
| R06 | 停止 | 宿主停止而容器/后台仍写 | STOP_FAILED，不恢复文件、不越过停止确认，强制入口也不能绕过 |
| R07 | 停止 | 回档中手动保存、重连、知识/测试迟到动作 | 恢复闸门与 fencing 拒绝写入/发布，不因旧 app/thread 相同恢复资格 |
| R08 | 备份 | backup 磁盘满、缺 blob 或 hash 错 | 不开始覆盖，保留当前状态与实际错误，不能强制忽略 |
| R09 | 严格 | AI 修改 A.java，用户新增 B.java，选择严格 | A 恢复、B 按范围撤销；backup 保留当前两者，旧上下文清除 |
| R10 | 保留 | AI 修改 A.java，用户新增 B.java | A 恢复、B 保留，保护 patch 与最终清单可核验 |
| R11 | 保留 | 同文件顶部 AI 改、底部用户改 | 顶部撤销、底部保留，不能按最后文件作者整份留或整份删 |
| R12 | 冲突 | AI 与用户改变同一函数同一区块 | 三方冲突/复核，用户可选目标/用户/手动；不静默 ours/theirs |
| R13 | 冲突 | 用户新增文件与旧快照同名、删除/重命名碰撞 | 文件级操作冲突明确，不套普通行 patch 覆盖 |
| R14 | 依赖 | 用户 patch 引用被撤销 AI helper，文本可合并 | 引用/编译/测试揭示失效，不能自动恢复未认可 helper 或假通过 |
| R15 | 认可 | 用户明确认可 AI 部分 hunk，其他不认可 | 只重放明确范围，源 actor 保留，不能全任务机械保留或删除 |
| R16 | 认可 | 认可后 Agent 再改同 hunk | 新变更不继承旧认可；记录内容 hash，回档保护具体版本 |
| R17 | 认可 | 用户批准执行、测试绿、继续聊天但未认可成果 | 不自动升级 user_approved，避免保留错误路径全部修改 |
| R18 | 来源 | Shell/格式化器/安装脚本产生源码变化 | 有前后内容与任务来源，生成器变化不能遗漏；用户同时写无法归因记 unknown |
| R19 | 来源 | 平台外部编辑/历史无记录 | 独立保护并请求处理，不按 mtime 或文件末次作者猜来源 |
| R20 | 重放 | 多个用户 patch 的 base 含 AI 改动 | 因果顺序逐项三方重放，仅带回 patch 变化，不复制 base 中整段 AI 错误 |
| R21 | 文件 | 二进制、CRLF/编码、权限、大小写、中文路径 | 内容和属性准确，无法安全合并的进入冲突，不损坏字节或串路径 |
| R22 | 文件 | symlink/junction/hardlink、绝对路径、../、.git 目标 | 受控拒绝越界，原项目与 Git 元数据不变，不能静默跳过后称全部恢复 |
| R23 | 快照 | 超过知识快照限额、wrapper/必要配置 | 完整恢复清单不采样；排除原因明确，必要内容缺失 TARGET_INVALID |
| R24 | 快照 | 相同大小/mtime 不同内容、目标 blob 到期 | 内容 hash 识别，缺目标不猜恢复或强制伪造 |
| R25 | 上下文 | 撤销节点/后续消息带唯一错误哨兵 | 真正 model request 无对应 messages/system/project 摘要，合法之前前缀仍在 |
| R26 | 上下文 | 摘要横跨回档边界 | 整份不复用，从合法原文重建；没有原文不可用旧摘要顶替 |
| R27 | 上下文 | 原 checkpoint 有 pending tool/旧 state | 不 replay/invoke 旧节点，使用新 thread/seed，原 Prompt 不自动发送 |
| R28 | 上下文 | store 项目记忆、检索缓存、图谱推断、旧工具结果 | epoch/来源过滤有效，跨线程长期 store 不能泄露被撤销事实 |
| R29 | 上下文 | 旧 report/backup 在宿主、文件搜索/Shell 越界 | 当前 Agent 无挂载/查询权限；人类只读接口不会成为模型工具 |
| R30 | 上下文 | 新旧代码内容 hash 相同但上下文不同 | 旧推断/summary 不复活；静态缓存仅经重新资格化可用 |
| R31 | 上下文 | 首消息回档，当前 app.initPrompt/标题含撤销内容 | 初始提示/自动标题/背景请求不重新灌入；输入框原 Prompt 不进入模型 seed |
| R32 | 上下文 | browser historyTail/重连/冷启动加载整段历史 | 服务端只投影合法前缀，原 thread resume 不得绕过切分 |
| R33 | 上下文 | 原持久化失败，尝试内存降级 | 明确错误，不以丢失 checkpoint 的降级假称可回档成功 |
| R34 | 语义 | 文本全合并但必需测试失败或依赖缺失 | VALIDATION_FAILED/待验证，不改标准、不自动装依赖、不显示成功 |
| R35 | 数据 | 新版删字段，严格回旧代码依赖旧字段 | 数据库不自动回滚，兼容性风险/失败明确，不能宣称应用恢复可运行 |
| R36 | 强制 | 保留模式冲突后明确选择异常强制 | 确认保护修改损失，有 backup，按严格目标重建且上下文仍纯净 |
| R37 | 强制 | 停止/权限/backup/目标/必需验证失败时强制 | 仍拒绝成功，不绕过硬门禁；任何合法用户消息可使用同异常流程 |
| R38 | 提交 | staging 冲突或用户等待处理 | 当前工作区不被半写，不激活半新 seed；继续编辑须退出使候选过期 |
| R39 | 提交 | backup 后、候选后、上下文准备后分别崩溃 | journal 与真实文件核对；无提交决定安全恢复/继续，旧错误上下文不重新激活 |
| R40 | 提交 | 文件切换后、DB 发布前/后崩溃 | 闸门阻止半状态使用；按已持久化决定完成一致文件/epoch，再解闸 |
| R41 | 提交 | Windows 文件被占用、跨卷替换或磁盘错误 | 不假设 rename 原子成功，记录实际错误/恢复状态，不能损失唯一备份 |
| R42 | 提交 | 重复回档请求、过期解决、迟到取消 | operation 幂等/CAS，不能双次发布或作用于新任务 |
| R43 | 失败 | 恢复保护代码作为事故退路 | 只保护文件，不恢复错误旧 AI 上下文；Agent 保持冻结/新合法边界 |
| R44 | 安全 | 其他用户读备份/提交冲突解决/强制 | 所有端点校验 app/owner/operation 及目标，不能凭 ID 越权 |
| R45 | 清理 | 超过 100 个回档点、长期会话、容量不足、用户清理及引用并发 | 所有有效回档点默认保留，不按数量/时间自动过期；容量不足显式处理，不静默删；压缩/去重后早期节点可恢复；主动清理展示影响，不清执行中/保存中/唯一恢复依据，不删用户 Git 或业务代码；既有缺失不伪造 |
| R46 | 全链路 | 干净基线重放回档+后续新输入 | 文件正确、用户修改符合方式、新模型请求零错误哨兵、旧 Git refs/index/历史不变 |

## 3. 覆盖用户明确要求的六个场景

- 不同文件：R10。
- 同文件不同位置：R11。
- 同一代码块冲突：R12。
- 用户修改依赖 AI 代码：R14、R20。
- 用户认可部分 AI 修改：R15–R17。
- AI 上下文纯净：R25–R33，必须检查真实请求而非 UI。

## 4. 分阶段门禁

1. 前端与锚点：消息范围、两方式、异常强制、保护差异、Prompt 回填；模拟状态须标明。
2. 窄严格恢复：先证明停止/备份/内容与上下文双恢复，不代表保留模式也完成。
3. 修改来源与合并：R10–R24，所有保护修改和未知来源有明确结算。
4. 上下文与资源：R06–R08、R25–R33、R37，实际模型请求、容器状态与权限有证据。
5. 全面故障恢复：R34–R46，干净重放、发布一致性和引用清理验证通过。

所有验收状态暂为待执行。选择了严格模式或强制模式不等于获准跳过失败检测；本轮仅创建文档。
