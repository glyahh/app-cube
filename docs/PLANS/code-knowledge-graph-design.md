日期：2026-10-03。
状态：主方案已确认；以下实现细节为设计建议，须逐步验证。未开始功能开发、候选安装或运行验收。
源码核对基线：`code_board` / `d4528044d36f38a91567cb5ceb138169af6a873d`。
研究依据：2026-10-02 调研的固定版本源码与官方资料，不把 main 分支能力、宣传数量或测试文件存在视为本机验收通过。

## 1. 范围与已确认要求

这是五项需求中的第五项。本文不重开导入、测试与回档需求；商业视觉功能仍暂缓。

1. 面向用户导入的任意语言、混合语言工程，不把语言白名单当产品最终边界。
2. 采用“统一图谱模型 + 通用解析器 + Agent 补全”。不为每种语言建设独立系统。
3. Tree-sitter 作为广覆盖语法解析基础，复用成熟 grammar、query 与适配器。
4. 能静态确定的关系直接入事实图；不能静态确定的关系由 Agent 检索当前仓库后尝试推断。
5. 用户界面区分“确定 / 推断”；证据不足允许保持未知，不要求 Agent 填满所有关系。
6. 所有语言使用同一套 PostgreSQL 图谱结构；文件依赖图与方法调用图是同一索引的不同视图。
7. 用户与 Agent 均可查询图谱。方法图优先展示局部邻域，支持搜索与展开。
8. 图谱只读；不提供用户直接编辑节点和边的能力。
9. 设置中可选择自动同步；未开启时手动更新。两种情况下代码变化都必须标记旧图过期。
10. 保留现有界面和架构，优先增量接入；只读索引不能偷偷安装依赖或运行导入工程。
11. 与会话回档保持一致：旧分支、保护备份、旧摘要、旧工具输出不能重新进入当前 AI 上下文。
12. 逐步骤独立验收，测试计划、源码实现、真实验证和发布状态分别记录。
13. Agent 补全采用 A：跟随图谱更新启动，遵循用户选择的自动/手动更新设置，只处理未解析和受影响项，不在每次更新时重新推断整个仓库。补全会产生模型调用成本。
14. 推断关系展示采用 A：默认显示，以虚线和“推断”标签区别于确定关系，用户可一键隐藏。展示默认值不改变证据类别或服务端事实查询过滤。
15. 取消独立 AI 知识问答功能，不规划图谱面板中的问答页签、输入框或专用问答服务。主聊天 Agent 的只读图谱检索、源码核对与图谱推断补全保留；取消问答不等于取消 Agent 使用图谱。
16. 图谱自动同步默认开启，用户可在设置中关闭；更新跟随启动 Agent 补全并产生相应模型调用成本。自动同步与应用是否启用图谱是两个不同开关，不改变导入后不自动安装依赖或运行项目的边界。
17. 自动同步设置采用 B：按用户全局保存，该用户的所有项目共用一个开关，不提供项目级自动同步覆盖。该设置只控制已启用图谱项目的同步，不替用户开启未启用的图谱功能；不同用户的设置独立。
18. 关闭自动同步时采用 A：允许已经开始的当前一轮更新及其 Agent 补全完成，不再启动新的自动轮次；需要立即停止时使用取消按钮。手动更新不因该开关关闭而取消，回档、权限变化和版本失效仍按独立安全规则阻断旧任务。
19. 图谱功能开关保留在设置中，新建或导入应用默认启用；创建过程中也允许用户手动开/关单个应用，并保存该应用的选择。开启后在合法源码就绪时自动后台生成第一版，不要求再点击生成按钮、不阻塞导入完成；关闭的应用不触发图谱解析与补全。新应用默认值不覆盖已有应用的明确选择。
20. 关闭单个应用的图谱时采用 A：保留已有图谱数据，不删除源码；重新开启时先校验当前代码版本与上下文边界，合法且兼容的结果可复用，否则更新。保留历史数据不意味着自动将旧图、旧推断或回档前上下文恢复为当前有效状态。
21. 关闭整个应用图谱时采用 A：取消该应用尚未完成的图谱解析和 Agent 补全，保留已完成数据；不允许旧任务晚到发布。只取消图谱专用任务，不取消其他应用或主编程任务，也不改写源码。此规则不同于关闭用户全局自动同步时允许当前轮完成的规则。
22. 新版图谱可用时机采用 B：本轮静态解析及 Agent 补全都结束且满足成功发布条件后再统一展示与对外使用，不提前发布静态半成品。等待期间保留上一版并正确标注过期；没有上一版时显示生成进度，不把流程结束等同于全部通过。
23. Agent 补全失败时明确提示用户出错，并自动额外重试一次；不默认降级为只发布静态图。重试仍失败时保持失败、保留合法旧版并正确标记过期，无旧版时显示失败。只有不得已且说明依据、能力损失与风险后，才由用户决定是否降级；项目级原则已沉淀到 AGENTS.md。
24. 生成图谱期间发生普通代码修改时采用 B：不因该修改直接取消正在执行的一轮，先完成该轮，再对最新代码更新。旧轮结果保留其快照归属，不冒充当前版本；回档、关闭应用图谱、权限撤销和主动取消仍阻断旧任务，不能借完成当前轮继续执行。
25. 默认图谱分析范围采用 A：以项目自身源码为主，第三方库以外部依赖/符号表示，不默认全量展开其内部调用。导入保留依赖目录不等于图谱默认深入索引这些目录；不改写导入过滤偏好，不自动安装或下载缺失依赖。
26. 文件依赖图与方法调用图通过图谱上方的一键切换按钮直接切换，沿用同一知识面板，不要求先点击文件节点或进入详情。两种视图读取同一项目、同一已发布索引版本；切换不等于重新生成、另建索引或改写源码。
27. 用户明确四层理解顺序：第一层项目总体架构；第二层文件依赖、归属与数据流；第三层主要模块中具体文件的作用；第四层代码方法之间的联系。按类似 BFS 的由表及里体验渐进展示，不把全图一次铺开，也不将图算法的最短距离直接当作架构层级。
28. 体验目标是流畅、灵动、精致且能帮助用户学到真实项目知识，不以截图漂亮或节点数量作为验收。性能阈值、视觉原型与学习效果仍待验证，不宣称已经实现或对任意规模绝不卡顿。
29. 用户明确只提供上述四层知识图谱，不增加“跟着看”、代表性功能分步导览或独立学习模式。职责、数据流与源码依据在对应层次中呈现；帮助理解项目不等于另建教学、考试或问答功能。
30. 首版视觉评审后，用户认可四层标识与节点关系的风格，保留四层知识图谱思想；完整星环不再作为必须形态。节点布局应灵动、有张力，并参考现有应用布局，不为图谱另造产品导航或独立开发界面。视觉稿仅作示例，节点、箭头和动效不构成真实分析或运行证据。
31. 第二版评审后，用户认可排版，但明确其颜色和样式与现有项目不匹配。保留该布局及四层结构，继续对齐现有主题、按钮、字体与边框样式；第二稿黑紫配色不作为已确认产品要求，后续样式稿仍需评审。
32. 第三版白/浅灰/蓝样式稿获用户“还行吧，先这样”的暂定认可，以其作为当前视觉基线，后续允许细调；保留已认可排版和四层思想。这不等于真实前端、动效、性能或源码关系验收通过，也不授权开始功能开发。
33. 第一层总体架构默认采用 A：技术协作架构，展示工程中真实存在的应用/服务、执行组件、存储及外部边界如何协作；节点内保留业务职责说明，再沿既有四层下钻。不是优先按登录、订单等业务功能组织首层，也不新增模式或页面。

### 不能偷换的目标

- 识别语言、解析语法、抽取实体、确定关系，是四种不同能力。
- 全语言是覆盖目标；当前缺少 grammar 或抽取规则时必须登记缺口，不能用目录树冒充完整调用图。
- 若 Agent 对暂缺静态能力的语言提出函数或关系候选，它们仍属于推断层，不构成该语言确定性解析已完成的证据。
- JSON、配置、模板等没有函数的文件，方法视图可以“不适用”，仍参与合适的文件关系视图。
- 静态确定的是相应规则下的目标，不意味着已证明所有运行时派发、反射或远程调用。

## 3. 职责与处理链路

```text
Java：权限、任务、源码快照、版本、取消、索引发布
  独立解析 Worker：语言识别、Tree-sitter、规则与可选语义工具
  Agent：当前快照内检索、未知项推断、结构化候选提交
  Java：候选与来源校验、PostgreSQL 持久化、版本化只读查询
Vue：文件图 / 方法图 / 证据详情 / 状态与覆盖
```

- 解析 Worker 与聊天 Agent 分离；可复用 Python 工具链，但不让大量解析长期占用聊天生命周期。
- 解析输入挂载只读，缓存和产物写到独立派生目录。不得将后端的原生缓存当产品权限入口。
- 静态抽取与结果保留不依赖模型成功；内部补全任务可读取本轮校验后的静态暂存结果。普通用户与主聊天 Agent 不提前使用本轮半成品；Agent 补全失败先提示并额外重试一次，不自动发布静态降级结果。
- 全仓库上下文指当前仓库可检索，不是一次发送全部文件。凭据、排除文件、旧分支与回档备份不在可检索范围。
- 需要构建、预处理、依赖安装或项目插件执行的工具，必须单独声明执行条件并遵循用户确认流程；不把静态索引当零副作用。

## 4. 统一模型：设计建议

### 默认分析范围

- 纳入应用自身合法源码，语言种类不作为排除依据；保持全语言覆盖目标。
- 第三方依赖默认作为外部目标，已导入的 node_modules、.venv 等依赖目录不因存在就全量展开内部调用。
- 不能把整个项目的所有非入口模块当第三方排除；业务源码、测试源码与依赖的归属需有依据，疑似业务源码不能静默丢弃。
- 来源无法可靠区分时明确报告范围疑点；静态目标缺少依赖信息时保留未知，不强行匹配到本仓库同名方法。
- 文件保留范围、图谱分析范围、模型可检索范围分别记录。外部节点不代表已经深入分析了第三方源码，也不代表该节点内部不存在调用。

`project_id` 对应当前应用 `appId`，不因为命名不同另建一套项目身份。跨 Java/Python 的 ID 使用 string。

| 对象 | 主要字段与职责 |
| --- | --- |
| `IndexRevision` | project/snapshot/branch/context_epoch、任务代次、清单 hash、工具指纹、覆盖、状态 |
| `SourceFile` | 相对路径、语言、内容 hash、编码、嵌入区域、是否分析及排除原因 |
| `Symbol` | ID、语言、类型、限定名、签名、所属文件/符号、源码范围、证据来源 |
| `ImportSite` | 所属文件、源码范围、声明内容、目标文件/外部包/候选及解析状态 |
| `CallSite` | 调用方、调用表达式范围、receiver、参数线索、目标或候选、解析状态 |
| `Relation` | 类型、起终点、调用点或导入点、证据类别、解析策略、索引版本 |
| `InferenceRecord` | 请求范围、模型与策略版本、理由、源码引用、候选校验结果、输入指纹 |

### 身份与位置

- 不以短方法名或行号作为唯一身份；限定名、签名、作用域和语言参与符号标识。
- ID 不截断完整符号名；展示名称与内部 ID 分开。
- 版本内身份必须唯一；跨版本复用仅在身份映射可靠时进行，不能默认重命名后仍是同一符号。
- 内部保留原文件字节范围；对接前端/LSP时明确 UTF-8 字节与 UTF-16 位置映射。
- Vue 等嵌入语言保留宿主文件、子语言及位置映射，不把临时虚拟文件路径泄漏成用户源码身份。

### 关系类型

第一步只验证 `contains`、`imports`、`calls_static` 与调用点；后续逐项增加 `references`、`implements`、`overrides` 和契约关系。

文件依赖图明确区分导入、文件间引用和文件间调用。方法图保留调用方、调用点与目标；外部包不强行绑成本仓库同名方法。
HTTP/RPC/消息/NDJSON/FFI 使用独立契约关系类型，不伪装同进程方法调用；动态目标无法确认时保留未知或候选。

## 5. 事实、推断与未知

用户界面保持“确定 / 推断”两类标签；“未知、分析失败、不适用”是状态，不造一条虚假关系。
推断关系默认显示，使用虚线和“推断”标签，提供一键隐藏；隐藏只是视图操作，不删除推断，也不自动改变 Agent 的检索策略。

内部证据类型建议：

| 证据类型 | 含义 | 默认进入事实查询 |
| --- | --- | --- |
| `syntax_fact` | 语法直接提取的结构或调用点 | 是；仅代表提取内容，不保证调用目标已解析 |
| `resolved_static` | 在明确语义规则与条件下已解析的关系 | 是；保留静态条件与策略 |
| `heuristic_static` | 同名、路径、框架规则等启发式关系 | 否，属于推断 |
| `agent_inferred` | Agent 基于当前源码提出的关系或实体候选 | 否，属于推断 |
| `runtime_observed` | 用户授权的某次运行实际观察 | 单独运行证据层，不自动冒充静态关系 |

`resolution_status` 独立记录 `resolved / ambiguous / unresolved / unsupported / failed`，不与来源混成一个置信度数值。

- 推断参与检索时必须显式开启并携带标签；精确调用查询默认只返回静态事实。
- 用户认可、高置信度或重复模型判断，均不自动升级为事实。
- 推断转为事实必须经过独立静态解析；原推断与新证据保留可追踪关系。
- 推断不能作为下一条确定关系的唯一依据；模型总结不得将候选省略标签后写入持久记忆。
- Agent 产生的实体也保留来源，避免虚构方法节点污染事实层。
- 没有调用边不能直接断言死代码；必须结合覆盖、未知调用点和语言能力。

## 6. Agent 补全：输入、输出与验证

### 输入

固定当前 project、snapshot、branch、context_epoch 和推断范围。提供未知调用点、已有事实、候选符号及允许检索的源码；任何旧版本检索结果均拒绝拼入当前请求。

### 可用只读能力

设计候选：`find_symbol`、`find_callers`、`find_callees`、`find_dependents`、`get_source_span`、当前快照文本检索。
未解析语言可读取同一快照的合法源码，不能为补全调用 Shell、修改项目或自行下载解析器。

### 结构化输出

每个候选提供调用点/关系类型、目标或候选集、源码引用、推断理由及已知限制；证据不足输出无法判断。
不允许直接写核心图表、不允许新增事实标签；统一由 Java 验证与入库。

### 校验

1. 检查对象归属、当前代次、请求身份、schema 和关系类型。
2. 检查引用文件、内容 hash、源码范围、端点存在性；新实体只能作为推断候选。
3. 检查权限、路径边界、敏感信息与旧快照访问。
4. 去重并保留理由；无法核验的提交拒绝入图，记录具体原因。
5. 引用位置有效只证明引用存在，不证明语义正确；模型自评分不等于准确率。

静态任务与推断任务分别记录状态，允许静态阶段完成而推断失败，但阶段完成不自动触发对外发布。已确认补全跟随图谱更新启动，全部阶段成功且校验通过后统一展示；补全失败明确提示用户并额外重试一次，仍失败不自动降级。具体调度、模型选择与不得已降级的判断细节仍需设计，不默认重复全仓推断。

产品任务级额外重试仅一次，不让模型或底层工具自行无限追加完整补全轮次。重试前重新检查取消、应用启用、权限、快照与上下文代次；复用合法静态暂存结果，不修改用户源码或扩大权限。正常的未知调用不是执行错误，不能为了消灭未知而强造目标。

## 7. 设置与查询边界

### 四层项目理解：已确认的展示目标

| 层次 | 展示内容 | 用户应获得的理解 |
| --- | --- | --- |
| 第一层 | 技术协作架构、实际组件与外部边界，节点内说明业务职责 | 系统哪些部分协作、怎样连接、各自负责什么 |
| 第二层 | 文件依赖、模块归属与数据流 | 哪些文件关联、数据从哪里来和到哪里去 |
| 第三层 | 主要模块中具体文件的职责 | 文件解决什么问题、在模块和流程中承担什么作用 |
| 第四层 | 方法之间的调用与相关联系、源码位置 | 具体实现如何连接，说明能否由代码依据支持 |

- 四层是理解层次，不是物理目录深度或调用图的 BFS 距离。共享文件、跨模块关系、循环依赖可以重复关联，但不能伪造唯一归属或让展开无限循环。
- 首层默认技术协作视角已确认；本平台可以展示 Vue、Java 接入层、Python Agent、存储和沙箱等实际组件及其协作。其他工程按真实结构组织，不强塞前端/后端/数据库模板；静态工具、库或单体工程没有的组件不造出来。职责与关系仍遵循事实/推断标签，展示组件不等于运行已经验证，不增加业务/技术模式切换器。
- 第二层回答关系与数据去向，第三层解释文件职责；二者不只是将同一图换个大小。业务模块识别和职责说明可能涉及 Agent 推断，依然标注依据，不因为出现在架构层就变成源码事实。
- 文件依赖不能直接冒充数据流。区分导入/调用、可静态分析的数据流、Agent 推断流程与实际运行观察；无依据时保留未知，不因连线动画声称运行已发生。
- 沿用同一知识面板、权限、快照和已发布版本；四层及文件/方法按钮不能串读不同版本。文件/方法切换是关系粒度选择，四层是理解路径，不要求增加四个独立页签。
- 保留全语言目标，不将所有工程强行套成 Web 请求或 Controller/Service 模板；没有对应层内对象时如实说明，不虚构模块或函数。

### 体验与学习：实现建议，仍需原型确认

- 流畅：按范围查询、聚合与渐进展开，稳定布局，取消失效查询；不一次下载或绘制全仓库关系。显示范围与未加载数量可查，不用静默丢弃关系换速度。优先复用现有画布，是否需要额外布局工具或 Worker 由测量决定。
- 灵动：进入层次时使用可中断的短过渡，选中对象驱动相关关系高亮；返回保留位置。避免持续漂浮、反复全图重排和必须等动画结束才能操作；提供减少动画与键盘操作。
- 精致：沿用应用工作台视觉语言，控制信息密度、字号、间距、关系标签与状态颜色；不能只凭截图认定可读或好用。
- 已确认的视觉方向：保留首稿的四层标识、圆形节点与克制高亮；星环可弱化为局部弧线或取消，不强迫所有实体按圆周排列。节点的疏密、层次和相关连线表达布局张力，不能把空间距离、装饰弧线或节点大小冒充源码关系与业务重要性。
- 现有布局复用基线：`AppChatView.vue` 的主聊天区与右侧工作台，通过知识页签承载图谱；复用现有放大/全屏能力及知识面板，文件/方法切换放在知识图谱内。保留主聊天不等于恢复已取消的独立知识问答。此处基于源码核对，不代表浏览器当前画面已经验收。
- 样式对齐基线：主主题由 `assets/theme.css` 与 `stores/appearance.ts` 提供，已有主色、字体、密度、减少动画和系统/浅/深模式设置。`workbench.css` 目前另有局部黑紫变量，不能只据它认定整站视觉。第二版排版已获认可，下一稿只调整样式；按源码浅色主题制作的白/浅灰与蓝色 `#1677ff` 是候选，不代表用户已确认当前浏览器配色或授权修改现有主题。
- 当前暂定稿：第三版保持第二版布局并使用白/浅灰/蓝样式，用户已同意先按此视觉方向。原图为 `C:\Users\gyb10\.codex\generated_images\01a0f842-126b-7f01-a883-bd92166ba2c9\exec-5b4ec709-e682-4d0a-ba5b-c43aa60a734a.png`，仅作静态设计参考，不是当前应用截图；最终前端仍需结合实际主题与交互独立验收。
- 理解：在四层图谱中呈现职责、输入输出、上下游和源码依据，不能仅重复文件名。不提供分步导览、独立学习模式、考试或打分，不恢复独立 AI 问答。

### 图谱视图切换

- 图谱上方提供一键文件/方法视图切换；不另建独立工作台或强制经文件详情导航。
- 两种视图共用同一索引和发布版本，切换不触发解析、模型补全或项目运行。
- 方法图仍遵循局部邻域优先、可搜索和展开的已确认规则；视图切换不意味着把全部方法一次绘入画布。
- 现有节点详情、源码定位和搜索继续服务两种图，不用节点点击代替顶部切换按钮。

### 同步与启用设置

已确认：自动同步默认开启，用户可关闭；关闭后手动更新；旧图只读且标记过期。已有明确设置不得在升级或重新进入项目时被默认值覆盖。
自动同步偏好按用户全局持久化，跨项目和重新进入后保持一致；项目是否启用图谱仍是独立边界。具体存储位置和跨会话通知方式待实现验证，不把全局偏好解释成全平台所有用户共用。

应用级图谱启用规则已确认：

- 新建与导入应用默认启用，创建过程中允许单独开/关，设置中保留该功能开关。
- 应用图谱开启且源码就绪时自动后台生成第一版；新应用尚无源码时不能生成一个空结果冒充完成。
- 创建时选择关闭的应用不创建解析/补全任务；关闭单个应用不修改用户全局同步偏好或其他应用的图谱选择。
- 应用启用状态和全局同步偏好是两种独立设置；不因此增加项目级自动同步覆盖。
- 关闭应用图谱保留已有数据；重新开启先核对当前 snapshot、context_epoch、工具兼容性和权限，再决定复用或更新，保留不等于当前有效。
- 关闭整个应用图谱时撤销该应用图谱任务的发布资格，取消进行中和未开始的专用解析/补全任务；取消未确认时显示取消中，不能宣称任务已经停止。已完成数据保留，未完成产物不得作为成功图谱发布；不停止主编程任务或其他应用任务。
- 首次生成与后续代码变更同步分别判断；用户关闭全局自动同步不等于撤销应用明确启用图谱的选择。

已确认的 Agent 补全触发规则：

- 自动同步开启：图谱因代码变化更新时，跟随更新补全未解析和受影响项。
- 自动同步关闭：不再因新的代码变化创建自动更新任务，已排队但尚未开始的自动轮次也不再启动；已开始的当前一轮及其 Agent 补全允许完成。用户手动更新仍跟随启动补全，无需另点补全按钮。
- 无需补全的更新不产生额外推断调用。重试等具体策略不得绕过当前版本、取消与权限约束。
- 跟随图谱更新不意味着自动安装依赖、构建或运行项目。

同步相关交互已确认：默认开启、用户全局保存、关闭后当前一轮可完成。取消按钮负责立即停止当前轮，未完成产物不得误发布为成功结果。允许完成不表示绕过源码版本、回档代次或权限校验；已失效结果不能强行成为当前图谱。

独立知识问答已取消，其推断读取设置不再对齐。主聊天 Agent 的图谱工具仍保留证据过滤、源码版本校验与推断标签；界面默认显示推断不能绕过这些约束。

技术建议：事实与推断使用一个存储模型、不同查询过滤，不维护容易串版本的两套权威数据库。
服务端必须执行过滤，不能只在前端隐藏推断。查询返回 snapshot、索引状态、覆盖、完整性与分页游标；存在未解析调用时空结果不代表没有调用。

## 8. 同步、发布与回档

```text
QUEUED -> SNAPSHOTTING -> DETECTING -> PARSING -> RESOLVING -> VALIDATING
  -> READY / PARTIAL / FAILED / CANCELLED / SUPERSEDED
```

补全使用独立任务状态，不让一个 READY 掩盖推断仍失败或未运行。普通查询仅返回已发布版本；本轮暂存静态索引仅供授权的专用补全任务使用，不能经普通图查询或主 Agent 工具提前读到。

- 使用内容 hash，而不是只靠修改时间/文件大小。
- grammar、query、resolver、依赖配置和语义工具版本变化均参与失效判定。
- 导入、导出、类型和配置变化传播到受影响文件；增量结果须与同条件全量重建等价。
- 普通编辑产生更新版本时允许当前轮继续分析其不可变快照；这一轮完成后再以最新代码安排更新。保留旧轮合法计算产物不表示发布为当前图，不能串入主聊天 Agent 的当前上下文；不为此扩大到回档后的旧分支访问。
- 新索引先写暂存版本，静态与补全阶段均成功并完成校验后再统一条件发布；项目、目标快照、任务代次和 context_epoch 必须仍匹配。文件图、方法图与普通 Agent 查询一起切换，失败重试不能偷偷触发降级发布。
- 事实/推断分别校验，同一读取不能混入其他快照。推断更新同样受条件发布约束。
- 回档推进上下文代次并撤销旧任务资格；历史缓存只能复用合法计算产物，不能恢复旧对话或旧推断输入。
- 手动模式不得偷偷重建：旧图可供用户看，Agent不得把过期关系当当前事实，可转读当前源码并说明图谱过期。
- 失败保留最近合法旧版本并明确过期；无合法版本时显示失败。任务取消或被替代不能显示成功。
- 普通编辑后旧轮计算结束与当前版本发布完成是两种状态：旧轮未成为当前图时不得显示“图谱已同步”，要继续显示当前代码尚待更新；关闭全局自动同步后不再启动下一自动轮，但已开始轮次仍按原规则处理。

## 10. 分阶段推进

| 步骤 | 目标 | 结束条件 |
| --- | --- | --- |
| P0 | 小样本比较候选与证据分层 | 静态关系、未知调用和推断正确分开；只读导出可回放 |
| P1 | 广覆盖实体与语法索引 | 按 grammar/语言登记解析、实体、导入、调用点能力，含嵌入语言 |
| P2 | 语义关系与契约适配 | 同名、别名、遮蔽、重载与跨语言边界无静默误连 |
| P3 | PostgreSQL、只读查询与现有界面 | 用户/Agent 查询同版本，方向、证据、分页完整性可核对 |
| P4 | 自动/手动更新与回档隔离 | 增量等价、取消收敛、旧任务发布与旧上下文读取被阻断 |
| P5 | 大型项目与 Agent 效果 | 规模、资源、正确率与定位效率有实测证据，不只比 token |

P0 是架构验证，不代替全语言产品验收。不能因几种语言样例通过就宣称整个需求完成。
每步完成后核对证据，再进入下一步；本文不授权执行 P0 或功能开发。
