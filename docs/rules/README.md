## 文档维护规则

- 目录统一使用小写简单英文词，按用途分类；文件名使用小写英文与短横线，日期使用 `YYYYMMDD`。README 保留惯例大写名称。
- 每份文档只保留一份正文；其他位置用链接引用。模块 README、根 README 和根 CONTEXT 保留为固定入口，运行提示词与依赖清单保留原位。
- 新文档按本页类别放置，更新所在目录 README 和文档总索引；跨主题证据按主要对象归入 reports/agent、reports/import 或 reports/workbench。
- 方案写目标和约束；测试计划写待验证场景；报告写实际版本、环境、命令、退出码、结果、原始证据位置与未验证内容。不要互相替代。
- 只把明确退出当前使用的材料放 archive；不得因文档较旧或尚未实施而擅自归档有效需求。历史结论保留日期，不把旧“待完成”恢复为当前任务。
- 移动文件时同步文档链接、脚本路径和本地协作规则。历史备份与外部绝对路径保留原值，缺失材料明确标注。
- 当前状态保留最新结论及权威范围；旧节点移到 archive/notes，并留下导航。更新状态只能依据本轮真实证据，不改写历史验收事实。
