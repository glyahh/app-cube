# 项目界面文案规范

采用 `ux-writing` 原则，适用于新增或修改的项目界面。

- 文案最小化：删除重复副标题、功能介绍和装饰性标语。按钮与布局已表达清楚的，不再解释，不用另一段说明替换已删除文案。
- 必要帮助按需显示，不常驻页面。
- 结果页聚焦结果、对象与下一步，不重复展示文件数量、大小、任务 ID 等技术元数据；数据留在内部状态、日志或按需诊断中。确认导入范围等确需核对的场景仍保留必要摘要，不因此删除业务数据或验证依据。
- 保留错误、输入限制、不可逆操作警告及必要权限/数据风险提示；失败、部分完成和未验证状态必须明确。
- 模拟真实使用的前端评审界面使用正常产品文案，不向用户展示 Mock、模拟、预览、待实现等开发标识或测试工具。数据与测试开关隔离在预览代码中，真实实现边界和验证结果记录在工程文档与交付报告里；不能把界面演示称为真实业务交付。
- 复用现有间距层级，分别核对模块、字段和按钮的间距、对齐及窄屏布局；不用增加说明文字弥补布局问题。

本规范不授权改变业务流程、验收标准或实现阶段。
