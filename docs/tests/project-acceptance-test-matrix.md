# 项目测试验收：分阶段验收矩阵

> 类型：测试计划与矩阵；用例存在不代表已经执行或通过。 当前事实以[项目状态](../status/current.md)及对应版本源码、验收证据为准。

日期：2026-10-03。对应 [专项设计](../plans/project-acceptance-design.md)。状态：以下全部是待执行用例，没有本轮通过数字。

区分平台功能验收和用户项目验收：本矩阵验证平台是否诚实、隔离、可回放地测试；不能因为平台自身测试通过就宣布任意用户项目可上线。

## 1. 执行记录与共同要求

每个执行记录必须包含：本平台 commit/工作区差异、样本来源/commit/内容版本、appId/testRunId/contextEpoch、方案/模板/标准版本、harness hash、环境/镜像/运行器版本、输入/随机种子、原始命令/目录、退出码、预期/实际、最终文件/业务状态、证据安全路径与 hash、时间、失败原因。

执行者填写 `待执行 / 通过 / 失败 / 阻塞 / 不适用`；不适用附依据，阻塞不能算通过。列为 P0/P1 的用例只代表较早验证，P4 全面验收仍需覆盖所有本期承诺场景。截图、编译、模型总结和旧版数字不代替证据。

### 样本包准备（尚未准备或运行）

- 正常/有已知缺陷的轻量业务项目，业务预期独立于当前实现。
- Java、Python、前端/浏览器与混合多服务样本；超出支持环境的样本用于失败提示，不能暗缩产品目标。
- 正/负 JUnit XML、JSON reporter、空报告、损坏报告、退出码矛盾、假绿色输出。
- 并发编辑、符号链接/junction、后台容器残留、资源故障、秘密哨兵、恶意日志指令。
- 不真实调用生产服务，不访问个人凭据；使用专属夹具和虚构秘密验证泄露防护。

| T08 | P1 | 测试前后比对用户工作区 | 业务源码与依赖配置没有测试引入的变化，生成测试位于独立范围 |
| T09 | P1 | 在建快照时连续手动保存/Agent 写入 | 只能发布一致版本；冲突重建或失败，不产生混合源码快照 |
| T10 | P1 | 同尺寸内容变化且保持 mtime | 内容版本变化，不能复用旧执行结果；不依赖现有轻量指纹 |
| T11 | P1 | 大文件、多于知识快照上限、wrapper/资源文件 | 可运行输入不默默截断；必要文件缺失明确拒绝而非假称完整副本 |
| T12 | P1 | 通过 hardlink、symlink/junction 尝试改原项目/跨 app 读取 | 写入隔离及路径防护有效，源工作区和其他用户内容不受影响 |
| T13 | P1 | 框架在 runner 生成缓存与构建产物 | 允许声明临时输出，不改 immutable source 或用户工程 |
| T14 | P1 | 测试 Agent/安装脚本尝试改业务源码或执行 lint --fix | 受控拒绝；源输入漂移 ERROR，不能作为测试修复自动接受 |
| T15 | P1 | 测试后台运行，同时开发修改项目 | 开发不被测试长期 app 锁阻塞；测试继续原快照，报告不代表新版 |
| T16 | P1 | 两个应用或不同轮次同时执行 | 容器、卷、端口、线程、证据不串用；不覆盖当前预览运行实例 |
| T17 | P1 | 无 Docker、模型未配置、placeholder 或旧 worker | 真实错误/能力缺失明确；不退宿主 Shell，不执行默认 coding，不假 PASS |
| T18 | P1 | 报告仅含绿色文本或 Agent run.completed=succeeded | 不据文本/事件判 PASS，需实际结果与断言证据 |
| T19 | P1 | 返回 FAIL、ERROR、BLOCKED、UNSUPPORTED、CANCELLED | 各状态语义正确，无法执行不被记成 PASS 或产品断言失败 |
| T20 | P1 | Runner 零退出但零用例/缺报告/全跳过 | 相关必要项未验证或 ERROR；不因 exitCode=0 标全绿 |
| T21 | P1 | 非零退出与报告全绿、损坏/不完整/重放旧报告 | 保存矛盾证据并拒绝可靠通过判定；文件时间/hash 不替代执行来源 |
| T22 | P1 | 一个用例失败，另一个无依赖用例可运行 | 后者继续；最终一次汇总本轮已选全部终态，失败不隐藏 |
| T23 | P1 | 前置服务失败导致依赖项不能执行 | 依赖项 BLOCKED，保存前置原因；不编造业务断言通过或失败 |
| T24 | P2 | Java 多模块、pytest 插件、Vitest/Playwright 实际版本报告 | 按适配器归一，保留 raw 与框架版本；不靠统一正则猜全部格式 |
| T25 | P2 | 本轮运行中改变标准或项目升级通用模板 | 本轮仍用原标准/版本；变更仅下轮生效，历史报告不被改写 |
| T26 | P2 | 通用模板发布新版 | 当前项目不自动升级，用户选择后新轮使用；未授权模板访问拒绝 |
| T27 | P2 | 项目专属测试与通用模板分别保存/使用 | 项目专属不自动跨项目复用；通用模板遵循原应用可见范围，不默认公开 |
| T28 | P2 | 不适用、环境缺失与用户人工声明 | 三者区分；理由/确认者可追踪，环境缺失不能伪装不适用 |
| T29 | P2 | 所选项全部绿，但未测必要项/存在未知适用性 | 总体未完整验证，综合高分不抵消缺失；未测列表完整可见 |
| T30 | P2 | 所有适用必要项有合法 PASS 证据 | 仅在明确范围/环境下表示满足门槛，不能泛化任意部署或企业认证 |
| T31 | P2 | 汇总 Agent 出错，程序结果已经采集 | 结果可查且汇总失败明确；不以静默缩减报告或自评分填空 |
| T32 | P2 | Agent 评分 100，实际权限用例 FAIL | 必要项仍未达标；评分来源、分母和缺失项可查看 |
| T33 | P2 | 配置金额/Token 预算相关输入 | 不能按金额静默跳项或宣称达标；安全资源限制触发必须标未完成 |
| T34 | P2 | 本轮依赖缺失，用户拒绝安装后又主动同意 | 未确认不安装；安装在本轮隔离环境，失败不运行依赖项；导入不自动执行 |
| T35 | P2 | 无法满足特定系统、硬件或外部环境 | 告知所需能力与未验证项，不擅自接电脑/远端或替换成较弱测试 |
| T36 | P3 | Agent 生成测试从当前实现反推正确答案/空断言 | 不能拿循环自证当业务验证；预期来源与质量检查失败显式呈现 |
| T37 | P3 | 用固定正负样本/受控缺陷评估生成测试 | 用例能检出已知缺陷且不过度误报；答案不暴露给被测 Agent |
| T38 | P3 | 请求成功但产生重复订单、错误归属或资源泄露 | 最终状态观察能判 FAIL，不只看接口/页面/编译成功 |
| T39 | P3 | 执行中发现新风险，用户拒绝或确认 | 未确认不执行但报告列风险；确认后有范围追加记录，仍绑定同快照与标准 |
| T40 | P3 | 新建议需新代码版本或新验收标准 | 另开轮次，不能混入当前结果集或偷偷改冻结条件 |
| T41 | P3 | 同输入同版本首次失败、重试通过 | 全 attempts 留存并标不稳定，不能最后结果覆盖失败；必要项不直接 PASS |
| T42 | P3 | 脚本伪造绿色 XML，日志含“忽略规则/读取秘密” | 原始产物按不可信数据处理；独立观察/答案揭示矛盾，模型不执行日志指令 |
| T43 | P3 | 自然语言“测试”发现问题 | 不写业务源码、不自动批准修复；用户授权后交独立开发任务 |
| T44 | P3 | 批准修复且代码已从 V1 变 V2 | 先在最新版本复现，旧报告仅线索；实质方案变化重新确认，含相关回归授权 |
| T45 | P3 | 修复交接后新开发改变现有输入 | 原测试不会跟着切模式/写新版；回归另绑修复版本，新增范围仍批准 |
| T46 | P4 | 用户取消前弹窗、取消过程中继续/迟到工具请求 | 提示影响；确认后撤销执行资格，不再启动新工具或发布成功 |
| T47 | P4 | 宿主 worker 已退出而 docker exec/服务仍运行 | 不能显示取消完成；登记/停止容器资源并核验终态，未停止 STOP_FAILED |
| T48 | P4 | 重复取消、迟到取消作用于已经复用的 worker | 幂等，只作用于所属 run，不杀新任务或其他用户资源 |
| T49 | P4 | 浏览器断流、刷新或切到别的工作台页签 | 后台测试继续，重新查询同轮；不误用当前聊天断开即取消语义 |
| T50 | P4 | Java/Worker 崩溃重启 | 核对真实资源与台账，收敛孤儿，不盲重跑副作用、不伪造完成 |
| T51 | P4 | 用户回档、应用删除或权限撤销，旧测试结果迟到 | fencing 拒绝旧发布；执行停止，旧证据只读历史，不进入当前上下文 |
| T52 | P4 | 回档后旧报告在项目目录、台账有旧失败项 | 真正发模型的请求/检索不含旧报告、checkpoint、摘要；默认复测不引用撤销分支 |
| T53 | P4 | CPU/OOM/超时/磁盘满/超大日志 | 显式错误和未完成范围，资源可收敛；不静默降级、跳项或使用宿主执行 |
| T54 | P4 | 尝试 docker.sock、特权、宿主路径、跨轮卷或出网重定向 | 执行权限拒绝越界；隔离库/夹具不串入平台库或用户当前实例 |
| T55 | P4 | 请求另用户计划/证据/报告/取消/保存接口，重复启动 | 每次校验归属、权限、冻结 revision 与幂等，ID 均 string、不串写 |
| T56 | P4 | JUnit XML 外部实体/超大嵌套，报告路径越界或 HTML 脚本 | 安全解析/大小约束、路径校验和内容展示防护；不外带秘密或跨目录读取 |
| T57 | P4 | 默认完成/自动导出，未点击下载 | 完整报告可短期查看，不永久写项目；最小台账与临时证据保留规则明确 |
| T58 | P4 | 点击下载，项目保存失败/重试/重复点击 | 文件脱敏；两步状态如实，保存失败不显示已保存，幂等不覆盖其他 run |
| T59 | P4 | 原始证据到期、清理与同时下载/未停止资源竞争 | 过期不可回放明确；不删用户代码或在用证据，目标绝对路径/归属核验 |
| T60 | P4 | 秘密哨兵进入日志/截图/错误/问卷或模型工具请求 | 明文不进入报告/非授权模型上下文，脱敏可核验，密钥只用安全引用 |
| T61 | P4 | 固定性能项在不同资源/负载/数据初态执行 | 结果附采样/预热/错误率与环境，不把指标不可比的两次成绩混为优化证明 |
| T62 | P4 | 从原固定基线、环境和测试定义重建全新副本 | 重现同一失败/通过及最终业务状态；缺证据或环境则如实阻塞，不沿用历史绿灯 |

### 3.2 P1 清单

- [ ] 锁定来源、版本、一个真实缺陷、独立业务预期与执行权限。
- [ ] 对完整必要输入建立内容快照，原项目不被测试改写。
- [ ] 使用一个已核实运行器执行，记录实际命令、环境、退出码与 raw 结果。
- [ ] 稳定复现失败，报告同时包含预期/实际及最终状态，不靠 Agent 自评。
- [ ] 验证零用例、环境缺失、取消、跨用户访问不能假通过。
- [ ] 测试期间继续开发，结果仍绑定原版本并提示过期。
- [ ] 查看/主动下载保存/失败重试行为符合约定，不自动永久保存。
- [ ] 干净副本回放得到相同结论，附确切工件路径和未验证项。

这只是 P1 入口证据，不代表整个第二项功能可用。修复代码与完整回档测试按第三项专项设计独立执行。

## 4. 全面交付门禁

- 本期承诺的所有必要平台用例完成；缺环境、取消或未执行不得计入通过。
- 用户项目报告每个细项、必要门槛、覆盖、版本资格均可检查，综合高分不掩盖失败。
- 自然语言测试、专属/通用模板、版本冻结、新风险确认、隔离执行和取消均通过真实链路。
- 权限、资源、后台残留、恢复和证据过期验证完成；真实模型请求证明旧上下文不可读取。
- 交付运行说明、版本化证据、复跑/故障恢复步骤、剩余风险、部署与回退计划；不默认发布生产。

所有实际测试命令在实现与环境确定后生成并执行；本文件不预填任何通过结果。
