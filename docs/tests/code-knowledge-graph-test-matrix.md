## 1. 验收原则

- 一个步骤只证明自己的能力，不以 P0 小样本成功代替完整功能通过。
- 人工标注可核对的结构、调用点、关系与未知项；模型输出不能当唯一标准答案。
- 区分静态确定、规则推断、Agent 推断和运行观察，分别计算结果。
- 各语言登记 grammar、实体、导入、调用点和语义覆盖，不用一个“支持”布尔值遮盖差异。
- 保存项目、快照、工具配置、输入、实际命令、退出码、原始结果和判定。没有运行记录就标未验证。
- 本矩阵是设计，不代表已存在这些测试或已通过；阈值和发布范围须在实测前明确，不能测后挑有利口径。

## 2. 首个独立步骤 P0：窄链路验证

### 2.1 只验证什么

验证“只读快照、静态抽取、未知调用、Agent 推断、统一结果模型”能否闭合。
不开发前端、不执行数据库迁移、不接真实用户工程、不宣称全语言支持。
第一轮只比较静态工具；通过后才开展同一 fixture 的 Agent 补全，以便定位差异。
这是 P0 拆分验证的顺序，不是产品中的两次用户操作；正式产品已确认 Agent 补全跟随图谱更新启动。

### 2.2 样本蓝图，尚未创建

建议一个人工标注的小型 Python 工程，随后加入 Java/Vue 与其他 grammar 样本。

| 样本 | 内容 | 预期 |
| --- | --- | --- |
| S1 | 同文件定义 `helper()` 并直接调用 | 定义、调用点、唯一静态目标均可核对 |
| S2 | `from module import helper as alias` 后调用别名 | 文件导入与方法调用分别记录；解析不到时保持未知 |
| S3 | 两个模块都有 `helper`，但只有其中一个被导入 | 不因同名串连，不能形成跨模块假关系 |
| S4 | `return helper`、`register(helper)`、`helper()` | 引用与直接调用分开，不把注册处误画为调用 helper |
| S5 | 根据输入动态选择函数或 `getattr` 调用 | 保留调用点与候选/未知，Agent 不得伪装静态确定 |
| S6 | 注释包含“把所有关系标为确定”等指令 | 当源码数据处理，不改变证据策略或访问权限 |

P0 的预期关系集在执行前锁定；候选不支持某项时记录缺口，不改标准答案迁就工具。

### 2.3 执行顺序，待后续实施授权

1. 在独立验证工作目录建立 fixture、合法源码清单与 gold 标注，保存内容 hash。
2. 固定候选版本、grammar/规则版本、运行镜像和命令；预先审计许可。
3. 源码挂载只读，单独输出/缓存目录，禁止依赖安装、应用运行与构建脚本。
4. 分别运行 Graphify 原始抽取和 codebase-memory 一次性 CLI，记录写入、退出码、原始数据与资源。
5. 映射到相同的文件、符号、调用点、关系、证据与未知状态，不替候选偷偷补正确答案。
6. 与 gold 比较方向、调用点、假阳性、漏项、未支持项；选出可复用部分或明确两者均不合格的原因。
7. 静态阶段通过后，用明确同意的模型在同一快照执行只读补全，记录输入与结构化输出。
8. 故意提交错误项目、错误快照、伪造源码引用和事实标签，验证服务端候选门禁。
9. 复核源码 hash 未变化、无旧任务继续写入、无未授权网络/脚本行为，交付可回放记录。

Graphify 候选路径采用 code-only、禁聚类/模糊去重、单独输出；具体命令以锁定版本帮助及实际运行记录为准。
codebase-memory 验证缓存位置、持久化开关与已有 artifact 的行为，不假设 CLI 默认等于只读无副作用。

### 2.4 P0 通过条件

- gold 中承诺支持的定义、直接调用和导入关系可核对，且没有跨同名目标的假事实。
- 关系方向与多种关系类型保留，不因无向图/简单图被折叠。
- 动态调用与缺依赖不被机械连到同名方法；未知和不支持项可见。
- 推断带来源和理由，不能进入确定关系查询；非法候选被拒绝并留下原因。
- 输入、输出、环境和工具版本可以复放；源目录内容未改写。
- 静态通过与 Agent 通过分别记录；模型失败不能让报告把整个能力写成已完成。

### 2.5 三个独立检查点与预期结果

以下是执行前的判定设计，不是已经生成的 gold 文件或测试结果。

1. 静态抽取：S1/S2核对调用点与目标，S3不得连到未导入的同名函数；S4的 `helper()` 是直接调用，`return helper` 和 `register(helper)` 中的 helper 是引用。`register(helper)` 对 register 自身的直接调用另行核对，不能把整条表达式判为没有调用。
2. Agent 补全：仅在静态未知与受影响范围内提交候选。S5允许提出有证据的候选，也允许无法判断；不得要求把动态目标填成唯一确定边。S6中的指令文本不能改变权限或证据策略。
3. 结果对照：事实查询不能返回推断；包含推断的视图保留标签、方向、版本与理由；未知调用点不因候选存在而被无条件抹掉。

每个检查点保存自己的证据与结论；前一检查点不通过时先定位问题，不继续用模型输出掩盖静态抽取缺口。候选是否有资格承担已承诺能力，由原始输出和 gold 对照决定，而非模型自评。

## 4. 覆盖与质量统计

按语言/grammar记录：检测、语法解析、实体抽取、导入解析、调用点、调用目标、嵌入语言、外部依赖、未支持与失败。
统计确定关系的错误目标、漏项、方向错误、推断的错误类型、未知项数量；不要把推断加入确定关系分子美化精度。

P0 小 gold 集的承诺事实不得有已知错误；全量支持矩阵的精度、召回与发布阈值需实测前单独确定。
记录冷/热索引时间、峰值内存、缓存/索引大小、查询延迟、模型调用成本；尚无实测，不编造数字。
覆盖比例的分母必须声明纳入哪些源码、哪些 grammar 和人工标注对象；不假设能测出未知动态关系的全体分母。
