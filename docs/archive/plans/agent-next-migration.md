# agent_next 迁移说明

从「单体 Java + LangChain4j」到「Java 接入层 + Python Agent 运行时」的迁移对照与操作步骤。

配套文档：接口契约见 [`docs/contracts/agent.md`](../../contracts/agent.md)；架构决策见计划文件。

## 一、MySQL → PostgreSQL 字段对照

列名统一改成 snake_case。**PG 会把未加引号的标识符折叠成小写**，原来的 camelCase
（`appName` / `isDelete`）不改就得到处写双引号，迟早有人漏掉。MyBatis-Flex 靠
`@Column` 映射，改列名不影响 Java 字段名与前端。

| MySQL | PostgreSQL | 说明 |
|---|---|---|
| `longtext` / `text` | `TEXT` | |
| `varchar(n)` | `VARCHAR(n)` | |
| `datetime` | `TIMESTAMPTZ` | 跨时区部署时 DATETIME 语义模糊 |
| `json` | `JSONB` | |
| `tinyint`（布尔列） | `SMALLINT` | 保留 0/1，与 Java 的 `Integer` 字段对齐 |
| `auto_increment` | 见下 | **不是所有表都该有** |

**主键语义（实测确认，别照 DDL 抄）**

| 表 | ID 实际来源 | PG 里的写法 |
|---|---|---|
| `app` / `user` / `chat_history` / `loop` / `memory_shrink` / `user_app_apply` / `user_loop_apply` / `user_personalization` | **雪花**（约 3.8e17，应用层生成） | 纯 `BIGINT PRIMARY KEY`，**不加 IDENTITY** |
| `conversation_memory_state` / `conversation_memory_ref` / `snapshot_history` | **真自增**（实测 1~148） | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |

`app` / `user` / `chat_history` 在 MySQL 里带 `auto_increment`，但实际值是雪花 ——
那个自增是建表残留。照抄会和应用生成的 ID 冲突。

另外 `app` 表里有一条 `id=1` 的历史种子数据，迁移时按原值搬，不要假定 ID 单调。

**列名对照**（camelCase → snake_case，逐表全列）

```

                          deployed_time, priority, user_id, is_beta, edit_time,
                          create_time, update_time, is_delete
```

> 这次先原样保留，避免顺手改出问题。

**DDL 位置**：`src/main/resources/db/migration/V1__init_biz_schema.sql`（12 张表）、
`V2__create_agent_run.sql`（新增的执行台账）。

**数据策略**：本项目不做历史 MySQL 数据搬迁。新链路只保证新写入全部进入 PostgreSQL；
旧 MySQL 保留给旧链路/历史查询，待业务确认后再处理。首次启动由 Flyway 创建 `biz`
schema 和新表。真实 PG CRUD 验收仍需在本机 PostgreSQL 服务可连接后执行。

## 二、归属变更

| 关注点 | 原来 | 现在 |
|---|---|---|
| LLM 调用 | Java（LangChain4j） | **Python** |
| 会话执行状态 | MySQL + Redis `cm:*` | **LangGraph checkpointer（PG）** |
| 长期记忆 | 无 | **LangGraph Store（PG）** |
| 代码检索 | ES `code_chunks_v4` 向量召回 | **Glob/Grep 工具驱动导航 + SearchTrace** |
| 路径 | 三处不统一，一处硬编码 | **统一 `WorkspacePathResolver`**；Java 下发，Python 不拼 |
| 副作用权限 | 分散在工具里 | **backend 执行侧统一校验** |
| 业务表写入 | Java | Java（不变）——Python 不碰 `biz` schema |
| 制品落盘 / 发布 | Java | Java（不变） |
| npm build | Java（`vueProjectBuilder`） | **Python**（Phase 3，随沙箱一起） |

## 三、迁移步骤

### 1. 装 PostgreSQL 并建库

```bash
createdb gly_ai_generate_code
psql -d gly_ai_generate_code -c "CREATE ROLE glyahh_biz LOGIN PASSWORD '...';"
psql -d gly_ai_generate_code -c "CREATE ROLE glyahh_agent LOGIN PASSWORD '...';"
```

### 2. 建 schema（Flyway 会做，也可以手工跑一遍看输出）

```bash
psql -d gly_ai_generate_code -f src/main/resources/db/migration/V1__init_biz_schema.sql
psql -d gly_ai_generate_code -f src/main/resources/db/migration/V2__create_agent_run.sql
```

### 3. 搬数据

**必须保留原 ID** —— 雪花值被 Java 与前端引用，重编号会把关联打断。

用 `pgloader` 最省事：

```
LOAD DATABASE FROM mysql://root:pass@127.0.0.1/gly_ai_generate_code
INTO postgresql://glyahh_biz:pass@127.0.0.1/gly_ai_generate_code
WITH data only, truncate, reset sequences
SET maintenance_work_mem to '128MB'
CAST type datetime to timestamptz drop default drop not null using zero-dates-to-null,
     type tinyint to smallint,
     type longtext to text,
     type json to jsonb
ALTER SCHEMA 'gly_ai_generate_code' RENAME TO 'biz'
;
```

搬完检查三件事：

```sql
-- ① 行数对得上（对照 MySQL 的 COUNT(*)）
SELECT 'app' t, count(*) FROM biz.app
UNION ALL SELECT 'user', count(*) FROM biz."user"
UNION ALL SELECT 'chat_history', count(*) FROM biz.chat_history;

-- ② 雪花 ID 原值保留（应看到 4.5e17 量级，以及 app 表里那条 id=1）
SELECT min(id), max(id) FROM biz.app;

-- ③ 自增序列要从现有最大值之后开始，否则新插入会撞主键
SELECT setval(pg_get_serial_sequence('biz.conversation_memory_state', 'id'),
              COALESCE((SELECT max(id) FROM biz.conversation_memory_state), 1));
SELECT setval(pg_get_serial_sequence('biz.conversation_memory_ref', 'id'),
              COALESCE((SELECT max(id) FROM biz.conversation_memory_ref), 1));
SELECT setval(pg_get_serial_sequence('biz.snapshot_history', 'id'),
              COALESCE((SELECT max(id) FROM biz.snapshot_history), 1));
```

> ③ 最容易漏。`pgloader` 的 `reset sequences` 未必覆盖到这三张表，
> 而序列从 1 开始的话，下一次插入就会撞上已有的主键。

### 4. 切换 Java 侧

`application.yml`：

```yaml
spring:
  datasource:
    driver-class-name: org.postgresql.Driver
    url: jdbc:postgresql://localhost:5432/gly_ai_generate_code?currentSchema=biz
  flyway:
    enabled: true          # ← 打开
```

同时把 MyBatis-Flex 实体上的 `@Column` 改成 snake_case 列名。

### 5. Python 侧

`.env` 填 `AGENT_POSTGRES_DSN`，checkpointer 与 store 会自动切到 PG（之前是内存降级）。
LangGraph 自己建 `langgraph` schema 下的 checkpoint 表，不需要 Alembic。

### 6. 收尾

- 删掉 `core/rag/`（ES 那套）
- 删掉 `core/memory/`（V4 双轨，被压缩机制取代）
- 删掉 `dev/langchain4j/` 8 个补丁类
- 删掉 `biz.memory_shrink` / `conversation_memory_state` / `conversation_memory_ref` / `snapshot_history` 四张表
- 前端把 `VITE_AGENT_STREAM_ENABLED` 打开，下线 `/chat/gen/code` 与 `/chat/gen/workflow`

## 四、回滚

每一步都可单独回退：

| 步骤 | 回退方式 |
|---|---|
| 切换 datasource | 改回 MySQL 连接串，`flyway.enabled=false` |
| 前端换协议 | `VITE_AGENT_STREAM_ENABLED=false` |
| 老链路整体 | `agent_next` 分支上的 Java 代码保持原样，切回 `master` 即可 |

**唯一不可逆的是数据搬迁** —— 但 PG 与 MySQL 并存期间两边都有数据，真出问题切回来就是。
确认新链路稳定后再停 MySQL。
